# PolyProp UI 设计规范

项目：ZhijuPoly / PolyProp Web 平台
更新时间：2026-09-14
规范来源：当前 React 平台 UI，以结构工作台及“聚合物相似性探索”作为高密度科研工作台参考模块。
使用规则：当前15个可见科研模块遵循本文件的公共页头、字体、主题和断点规范。页面级规范负责业务布局、控件密度及科学媒体；公共页头仅允许本文件明确列出的滚动例外，不独立覆盖标题几何。实验数据、实验流程 Demo 和 Agent 嵌入工作区不在本次统一范围。

---

## 1. 设计方向

PolyProp 是科研生产力平台，不是营销展示页。界面应当冷静、精确、可重复，适合研究人员长期高频使用。

- 采用固定左侧平台侧栏 + 右侧工作区的产品布局。
- 使用冷灰平台背景、白色工作面、低饱和蓝色和青色作为主强调色。
- 优先保证信息可扫描、布局稳定、控件高效，避免装饰性构图。
- 视觉资产只用于表达真实科研状态，例如分子结构、3D 构象、图表、表格和工作流数据。
- 禁止把黑金电商风、Liquid Glass 营销效果、横向滚动落地页、巨型 Hero、装饰渐变作为平台默认方向。

---

## 2. 基础规范

### 2.1 色彩

- 应用背景 `--np-theme-bg`：`#edf3f9`，用于平台和工作区底色。
- 侧栏背景 `--np-sidebar-bg`：`#f7f9fc`，用于固定导航外壳。
- 白色工作面 `--np-theme-surface`：`#ffffff`，用于编辑器、卡片、面板和输入区。
- 悬停背景 `--color-bg-hover`：`rgba(15, 23, 42, 0.05)`，用于按钮和菜单悬停。
- 激活背景 `--color-bg-active`：`rgba(15, 23, 42, 0.09)`，用于选中导航和菜单项。
- 主强调色 `--np-theme-blue`：`#2563eb`，用于主要科研操作和聚焦状态。
- 成功和选中强调 `--np-theme-success`：`#10b981`，用于正向状态和已选指标。
- 危险色 `--np-theme-danger`：`#dc2626`，用于错误和破坏性操作。
- 主文本 `--np-theme-ink`：`#0b1f3a`，用于标题和关键标签。
- 次级文本 `--np-theme-muted`：`#58708d`，用于正文标签和元信息。
- 弱文本 `--np-theme-faint`：`#8da1b8`，用于提示、时间戳和被动反馈。
- 边框 `--np-theme-border`：`rgba(51, 83, 126, 0.18)`，用于细分隔线和卡片轮廓。
- 任务状态统一使用公共文字／浅底／边框角色：排队和已取消用 `neutral`，运行中用 `info`，取消中用 `warning`，完成用 `success`，失败用 `danger`。状态徽标使用纯色背景；科学类别和优化目标色保持业务语义。

### 2.2 字体

- 标题使用 `--font-heading`（Exo），正文使用 `--font-body`（IBM Plex Sans），数值、SMILES、ID使用 `--font-mono`（Roboto Mono）；中文回退沿用全局声明。
- 页面标题20px／2K 28px，行高30px／42px、字重750；工作面标题18px／24px。业务字段保留现有密度。
- 禁止用视口宽度缩放字体大小。
- 普通正文字距保持 `0`；页面标题使用 `-0.02em`。只有小型大写徽标可以使用轻微正字距。
- 工具页面内部不使用 Hero 级大字号。

### 2.3 间距和几何

- `--space-xs`：`4px`，用于密集图标和文字间距。
- `--space-sm`：`8px`，用于标准控件间距和灰色分隔。
- `--space-md`：`16px`，用于紧凑卡片内边距。
- `--space-lg`：`20px`，用于主要科研工作区内边距。
- `--space-xl`：`32px`，用于较大内容区的内部间距。
- 平台模块使用AppShell右侧工作区；侧栏宽度沿用响应规则。标题坐标扣除侧栏及移动顶栏，不假定固定侧栏宽度。
- 标题工作区满宽；正文保留各页1040px／1560px工作列或按高度适配的结构画板。
- 15个原生模块使用满高、零外边距AppShell，公共页头统一预留顶部空间。
- 卡片和固定格式工具必须定义稳定尺寸，例如宽高、宽高比或明确的 flex 约束。
- 默认圆角：按钮 `6px`，胶囊和小面板 `8px`，大型编辑器卡片 `14px`。

### 2.4 阴影

阴影应克制使用，优先用边框和轻量层级表达结构。

- 主工作面使用 `--np-theme-surface-shadow`，普通与2K两档值由公共主题文件维护。
- 按钮、浮层、抽屉保持各自现有层级，不与主工作面共用同一强度。

## 3. 布局模式

### 3.1 AppShell

- 桌面端采用固定左侧侧栏和右侧工作区。
- 侧栏使用安静的导航分组、白色激活行、青蓝色选中图标和紧凑文本。
- 根节点显式使用 `.np-module-page`、`ModulePageHeader`；根节点预留页头高度，正文使用 `.np-module-page-body`。默认正文独立滚动，单体正向聚合遵循3.4节的整体滚动例外。
- 全功能科研模块可以使用页面级 full-bleed 规则，但必须保留全局侧栏。

### 3.2 科研工作区

- 第一屏直接展示真实工作面，不为工具页面制作落地页。
- 控件应靠近它影响的对象。
- 优先使用一个主画布或编辑器工作面，再配一个统一的结果或分析面板模式。
- 当高密度工具需要变窄时，两侧留白必须只是背景，不放装饰圆点、渐变块或卡片。

### 3.3 右侧分析抽屉

- 当主画布需要居中时，结果探索使用右侧贴边抽屉。
- 默认宽度 `380px`；实现可拖拽时范围为 `320px` 到 `560px`。
- 抽屉应统一承载 loading、空状态、错误状态和成功结果。
- 抽屉贴边时不额外叠加装饰性外框或重阴影。

---

### 3.4 公共页头与主题来源

| 参数 | 普通视口 | 宽≥2000且高≥1120 | 宽≤899 |
|---|---:|---:|---:|
| 左／上边距 | 20／22px | 36／30px | 16／20px |
| 字号／行高 | 20／30px | 28／42px | 20／30px |
| 标题下间隔 | 10px | 12px | 10px |
| 页头高度 | 62px | 84px | 60px |

- 默认各尺寸固定页头、正文独立滚动；一个可见模块仅保留一个页面级h1。
- `ModulePageHeader` 提供 `actions` 插槽，辅助操作与标题同行，不改变标题坐标或62／84／60px页头高度。AI 浏览总结在桌面端默认位于操作区最右侧，使用30px小工具按钮，原生2K档为42px；知识检索与数据库筛选改放现有就绪状态右侧，高度36px／2K档54px。状态和错误说明使用可通过点击外部或Escape收起的浮层，不增加占位。
- 记录入口跟随平台导航断点：宽度<1024px时仅放在现有56px移动导航右侧，按钮40×40px，页面标题和移动侧栏不重复放置。未接入模块保留禁用开始入口；已有会话时均可结束、查看和重试。
- 总结面板为应用级单例，会话跨模块延续。Agent首页桌面入口复用平台侧栏品牌动作区；旧实验数据页、实验流程Demo分别复用现有导航和工具栏，不套用原生页头布局。详细行为见 `docs/browsing-recording-ui.md`。
- 唯一滚动例外为单体正向聚合：按后续业务要求，单次／批量模式均由模块根节点整体滚动，标题随正文移动。初始标题坐标、字体及页头占位仍遵循上表；不得将例外推广到其它14页。验收需实际滚动根节点并验证标题移动量与滚动距离相反，不能跳过该模块的滚动检查。
- 标题按视口断点判断，正文按容器宽度排版。除上述主动滚动例外，状态、错误、抽屉和标签变化不改变标题坐标。
- 几何来源为 `frontend/src/styles/module-page.css`；基础视觉来源为 `frontend/src/styles/workbench-theme.css`。私有变量引用公共角色，不重复写基础颜色。
- 主蓝／深蓝／辅助青为#2563eb／#1d4ed8／#0891b2；成功／警告／错误为#10b981／#f59e0b／#dc2626。浅底状态文字使用独立深色前景角色以保持可读性；状态底色与边框分别使用公共`*-soft`、`*-border`角色。服务检查失败与服务暂不可用分别表达错误与警告。
- 主表面圆角14px／2K 20px，阴影使用公共surface角色；图表类别、原子元素、优化目标保留科学语义色。
- 主题仅作用于接入的模块，不通过全局h1、button或card选择器改写排除页面。

## 4. 组件规范

### 4.1 按钮

- 常见命令使用 Lucide 图标；不够自解释的命令使用图标 + 文本。
- 标准小工具按钮：高度 `30px`，圆角 `6px`，白色背景，`1px` 细边框，水平内边距 `12px`，图标文字间距 `6px`。
- 悬停状态应轻微变化，例如灰蓝边框和文本强调，不能造成布局跳动。
- 禁用控件必须明显不可用且不可交互。组合运行按钮禁用时使用 `opacity: 0.45`。

### 4.2 输入和胶囊

- SMILES 等科学字符串输入区应使用适合代码阅读的排版。
- 只有存在内容时才显示浮动复制和清空按钮。
- 反馈文本应出现在相关胶囊内部或正下方，不把局部反馈放到全局 toast。
- 示例值可以出现在 placeholder 中，但不能作为默认真实输入值。

### 4.3 卡片和面板

- 卡片只用于重复结果、编辑器工作面、模态框和确实需要框住的工具。
- 禁止把页面大区块做成装饰性卡片，再在里面嵌套卡片。
- 结果卡应展示结构图、关键指标、来源和可追溯数据。
- 面板标题、指标标签和状态文本必须使用可读的深色文本，不能出现白底白字或低对比文本。

### 4.4 Loading、空状态和错误状态

- Loading 使用骨架屏或局部占位，不让页面整体闪烁。
- 空状态只给出简洁下一步，不写营销文案。
- 错误状态保留操作上下文，并提供可恢复动作。
- 状态组件的尺寸应稳定，不能因为文案长短导致主布局跳动。

### 4.5 2D 和 3D 科学媒体

- Ketcher 画板是主要 2D 结构输入面，必须保留真实编辑器能力。
- 3D 构象必须使用真实结构预览，不使用假 Canvas 动画替代已有结构图。
- 2D 和 3D 切换应保持输入状态，不丢失 SMILES 或画布内容。
- 分子结构图、SVG 和 3Dmol 输出必须走安全渲染路径。

---

## 5. 动效和交互

- 动效用于解释状态变化，不用于装饰。
- 翻转、抽屉展开、下拉菜单和反馈出现应短促，避免影响科研操作效率。
- 运行后才展开分析抽屉，初始状态不占据结果区域。
- 用户输入、导入图片、生成 SMILES、切换 3D、运行查询之间的状态必须可追踪。

---

## 6. 禁用模式

- 不使用黑金电商配色作为当前平台标准。
- 不使用 Liquid Glass、玻璃拟态营销卡片或大面积半透明叠层作为默认风格。
- 不制作横向滚动营销页或 Hero 优先页面来替代工具主界面。
- 不使用装饰性渐变球、光斑、纯氛围背景图。
- 不把右侧结果区做成全宽内容流，除非页面级规范明确要求。
- 不牺牲真实 API、真实 Ketcher、真实 3D 结构来追求静态视觉一致。

---

## 7. 交付检查清单

- 左侧平台侧栏和右侧工作区关系清晰。
- 页面第一屏直接提供可用工具或数据，不是营销介绍。
- 背景、工作面、按钮、胶囊、卡片颜色符合冷灰 + 白色 + 蓝青强调方向。
- 控件尺寸稳定，文字不重叠、不溢出。
- Loading、空状态、错误状态、成功状态都已覆盖。
- 真实 API、Ketcher 编辑器实例、3D 预览和安全结构渲染不被静态 mock 替代。
- 修改前后运行 `npm run build` 和 `git diff --check`。
