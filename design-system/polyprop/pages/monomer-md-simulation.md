# 单体 MD 模拟页面设计规范

页面：单体 MD 模拟 `/monomer-md-simulation`
参考实现：`MonomerMdSimulationPage`
更新时间：2026-09-02
范围说明：本规范不适用于示例结果工作台 `/md-simulation`。

---

## 1. 页面定位与数据边界

- 页面是 `/api/v1/monomer-md/*` 真实异步 Worker 的操作与分析工作台，保留快速 DensityDemo 及 Density、Transport、HVap、Dielectric、Compressibility 五种正式协议。
- 页面不模拟阶段或进度；状态、阶段、进度、排队位置、时间、结果与产物都来自任务响应。
- 正式任务列表属于可信单租户下的全局任务，不使用“我的任务”文案。任务中心只列正式历史；演示任务通过当前结果或 `?job=<32位十六进制ID>` 恢复。
- 不展示 `artifact_root`、服务器绝对路径或托管目录；只有服务返回真实 URL 时才提供“打开”操作。

## 2. 工作台骨架

- 页面进入 AppShell 的满高 `p-0` 科研工作台分支，平台侧栏负责模块切换，不显示返回首页按钮。
- 复用结构工作台冷灰蓝网格、蓝青 token、白色工作面、细边框和浅阴影；主工作面必须挂载公共 `np-sw-accented-surface`，在上边缘显示与 `/md-simulation` 一致的内缩蓝青渐变线。专属样式全部位于 `.np-monomer-md-simulation` / `.np-mmd-*` 命名空间。
- 页面滚动层铺满工作区，滚动条固定在最右侧；标准内容列为 `1040px`，`2000×1120` 以上扩展为 `1560px`。
- 标题层级与 `/md-simulation` 对齐：平台页标题下先放细强调线和紧凑服务工具栏，白色工作面内部使用“渐变图标 + 当前工作区标题 + 单行说明 + 右侧徽标”的统一标题头部；不在工作面上方另设英文 eyebrow 或营销式大标题。
- 主工作面稳定包含标题头部及 `模拟配置 / 任务中心 / 结果分析` 三个一级 Tab。三个 Tab 共用外框、标题高度和滚动边界，并使用完整 `tablist / tab / tabpanel` 语义与方向键导航。
- 顶部紧凑服务工具栏分别表达检查中、准备就绪、部署排空、容量已满和不可用；“准备就绪”只显示绿色发光圆点与单行状态文字，不使用勾选图标或下方说明。容量仍用 `can_submit` 与 `formal_can_submit` 分别判断快速演示和完整 MD 提交能力。
- 工具栏状态与刷新统一使用 IBM Plex Sans、`650` 字重，标准视口为 `13px`，`2000×1120` 以上为 `18px`；2K 模式下模式入口、输入、提示、按钮、任务与结果数据也必须使用完整的大屏字号层级，不允许只放大标题。
- 中文说明、分页、状态与任务语义值统一使用 IBM Plex Sans 中文回退体系；Roboto Mono 仅用于任务 ID、SMILES、JSON、纯数值指标及英文技术标识，禁止整段应用于中英文混排文案。分页文字与按钮在标准视口统一为 `12px`，`2000×1120` 以上统一为 `15px`。

## 3. 模拟配置

- 快速演示 SMILES 初始为空，示例必须由用户显式载入；提供复制、清空、导入共享结构、前往结构工作台及可取消的安全 2D SVG 预览，不挂载第二个 Ketcher。
- DensityDemo 不是静态示例结果：当前部署由 Worker 真实执行 300 步 ByteFF2 NPT 分子动力学。配置页只在右侧只读执行步数展示具体数字；标题下说明、模式入口、提交状态和“开始快速模拟”按钮不重复强调。若服务返回不同默认步数，则显示服务真实值。
- 演示输入边界为非空、最多 1000 字符且不含 `*`；化学有效性仍以后端为准。实际执行步数只读展示；因为 300 步不足以达到平衡，结果不能作为物理密度结论，但不得写成仅用于模拟进度或预设结果展示。
- 正式协议切换卡采用紧凑单行布局，左侧直接使用 Density、Transport、HVap、Dielectric、Compressibility 英文协议名，右侧显示可用状态，不并列中文翻译或使用上下分离造成大面积留白；协议卡必须由 `/protocols` 同时确认 supported、runtime_ready 和目录可用性，未知或未就绪协议可查看草稿但不得提交。
- 正式编辑器提供结构化表单和高级 JSON。结构化编辑先写入局部草稿，只有完整合法时才在原始完整对象上替换已知路径；未知顶层字段、嵌套对象和数组不得丢失。
- 组分名称非空且唯一、摩尔配比为有限正数、SMILES 非空且不含 `*`；名称变更必须同时更新 `components` 与 `smiles` 键。温度为有限正数，`natoms` 为 `1–10000` 的整数，HVap 恰好一个组分。
- Dielectric 的缺失字段保留隐式缺省：2M NPT、6M NVT、500 采样间隔和 8M 总步数；服务模板显式为 2M、8M、1000 和 10M 总步数。编辑其他字段不得物化缺失值。
- Compressibility 的 `npt_steps` 缺失时显示 5M；显式值必须严格大于 1M。Density、Transport、HVap 的预计步数分别为 1.5M、15M、6.5M。
- 高级 JSON 允许暂时无效，只有“应用 JSON”会替换合法配置；离开带未应用修改的编辑器需要明确确认。`protocol` 固定为当前协议，三种目录字段仍在提交前恢复服务托管值，但界面不展示这些开发实现字段或托管路径说明。
- 五个正式协议保存独立的最后合法草稿。版本化 sessionStorage 保存运行模式、演示 SMILES、当前协议、合法配置与模板指纹；模板变化时明确选择保留草稿或恢复新模板。

## 4. 任务与深链

- 创建成功和选择历史任务时写入 `?job=`；刷新、冷启动和前进/后退恢复任务并继续轮询。React Strict Mode 首次挂载取消恢复请求时必须清理内部选中 ID，并在重挂载后重新请求，不能永久停留在加载态。非法 ID 不请求后端，404 统一提示“任务不存在或已到期”。恢复区只显示“正在读取任务的最新状态和已有结果”，不向普通用户暴露查询参数格式等实现细节。
- 创建请求在获得新 ID 前失败时不得清空或替换旧任务、URL 和结果；新 ID 返回后才切换选中任务。
- 活跃正式任务在任务中心可见或已知存在正式活跃任务时每 5 秒刷新。正式历史固定每页 10 条，只在打开任务中心、筛选、分页、终态、取消、删除或手动刷新时更新。
- 协议与状态筛选使用工作台专属的组合框与浮层列表，视觉上延续冷灰蓝、蓝青微光和等宽英文标签；支持方向键、Home/End、Esc、Tab、外部点击关闭及明确焦点，不使用样式无法跨浏览器统一的原生下拉弹层。
- 取消、删除产物和删除记录均要求确认；删除当前任务记录后清除查询参数。关闭提交只影响新建任务，不影响只读浏览和任务操作。
- `progress_percent` 始终按 `0–100` 直接钳制，数值 `1` 显示为 `1%`。

## 5. 结果分析

- 当前任务头部展示 ID、模式、协议、状态、真实阶段、进度、排队位置、开始/结束时间和真实可用操作，并注明结果对应当前选中任务的提交参数。
- 结果分析采用统一五级文字层级：标准视口下二级 Tab 为 `13px / 10.5px`、字段标签为 `10.5px`、正文与数据为 `12px`、分区标题为 `16px`、关键指标为 `17px`；`2000×1120` 以上分别提升为 `17px / 14px`、`13px`、`15px`、`23px` 和 `21px`。中文说明与单位使用 IBM Plex Sans 中文回退，任务 ID、时间、数值、SMILES 和文件名使用 Roboto Mono。
- 二级结果 Tab 为 `概览 / 曲线 / 构象 / 输出文件`：
  - 概览：提交信息、体系组成、摘要指标、协议指标与科学有效性说明。暂不展示只有设备编号、内部引擎名和粗粒度版本号的运行环境卡；提交信息改为全宽横向信息带，Density/Transport 为五项单行，HVap 追加单组分约束，Dielectric 追加 NPT/NVT 步数与偶极采样间隔，Compressibility 追加 NPT 步数；平板两列、移动端单列。协议值始终展示后端原始英文名称，不翻译。只有在 Worker 能随任务持久化 GPU 型号、显存与内存等可解释快照后，才重新引入运行环境信息。
  - 曲线：密度、温度、能量选择器；能量视图只展示总能量曲线，单位为 `kcal/mol`。即使 v2 正式结果同时携带势能、动能序列，页面也不绘制分解曲线；v1/legacy 结果保持兼容。
  - 构象：v3 结果按真实 `x/y/z` 坐标播放关键帧轨迹，支持拖拽旋转与滚轮缩放；v1/v2 或解码失败时明确回退为单帧“构象预览”。
  - 输出文件：只显示安全文件名、类型、大小和真实 URL 操作；无 URL 不生成下载或打开按钮。
- 正式指标把值与 `*_std` 合并显示为“值 ± 标准差”，`*_unit` 与 `metrics.units` 只作单位元数据。Transport 将 `components` 与 `Dself_inf` 配对，数组错位时显示契约异常并保留原始 JSON。
- 未识别字段进入折叠“原始指标”，不丢弃数据也不猜测单位。只有正式结果明确返回 `physical_result=true` 时才标记为正式物理结果。
- DensityDemo 概览必须显示“真实 MD 计算”及任务实际请求/完成步数，同时说明步数不足、尚未平衡；不得把真实 Worker 计算降格描述为单纯链路验证。

### 5.1 构象时间轴

- v3 正式可视化契约新增 `trajectory_timeline`，只嵌入覆盖整个阶段的真实 DCD 关键帧，不把完整 DCD 或线性插值得到的伪帧写入 JSONB。源轨迹达到上限时固定保留 60 个关键帧；始帧、末帧、前 10 个保存帧、热力学曲线极值/突变帧优先保留，其余名额按全时间范围均匀补齐。
- `trajectory_preview` 继续保存阶段最终帧，作为 v1/v2 结果、旧快速演示和时间轴解码失败时的兼容回退；不得把它描述为完整轨迹。
- 帧时间仅在 state CSV 与 DCD 能可靠对齐时写入；无法对齐时保留真实 `frame_index`、省略 `time_ps` 并返回稳定 warning，禁止按配置步长猜测。
- 时间轴所有帧使用同一组原子身份，最多 2000 个原子。采样按组分配额选择完整 molecule/residue，稀有离子不会因低丰度消失，任何被选中的 residue 都必须包含全部原子。
- 构象区标题使用“构象轨迹”，说明固定为单行短文案。点云颜色按原子元素而非 DMC、EC、PF6 等组分区分，画布内必须展示当前数据实际包含元素的颜色图例。
- 周期体系按最小镜像重建并整体回卷每个 residue，避免单个分子被盒边界切断；每个关键帧同时保存当帧周期盒。
- 原子元数据只保存一次；坐标按 frame-major 顺序以 `0.01 Å` 精度量化，采用 `int16 delta + gzip + base64` 有界编码。前端校验 60 帧、2000 原子、解压长度和编码类型后才分配坐标数组。
- 前端在现有 Canvas 点云上提供播放/暂停、首帧、下一帧、时间滑块、0.5×/1×/2×速度和循环控制，切帧时保持相机旋转与缩放。界面明确显示“关键帧数 / DCD 源帧数”，播放只经过真实关键帧。
- `2000×1120` 以上轨迹按钮与主控文字分别至少为 `14px / 13px`，交互提示与元素图例为 `13px`，HUD 与三轴微标签为 `11px` 以上；不得沿用标准视口的 `8–10.5px` 微字号。
- 多阶段任务的时间轴继续受统一 NPT/NVT 阶段选择器控制；换阶段重置到该阶段默认帧，切换结果 Tab 不重置当前帧。`prefers-reduced-motion` 下不自动播放。
- 完整 3000 帧播放、轨迹下载、距离随时间变化等能力需要独立的受控轨迹流式接口或对象存储，不通过任务详情 JSON 承载，仍不纳入本期能量分解改动。

## 6. 响应式与可访问性

- `<900px` 使用 `12px` 两侧安全区，配置、任务、指标和结果布局按可用宽度降为单列；`390×844` 下所有操作可达且无横向溢出。
- 所有交互控件保留可见焦点，JSON 错误通过 `aria-invalid` / `aria-describedby` 关联；危险操作使用确认；遵循 `prefers-reduced-motion`。
- 被省略号截断的任务元数据必须同时提供鼠标悬停和键盘聚焦可见的完整值，不能只依赖被裁切文本。
- 视觉验收覆盖 `1920×1080`、`2560×1440`、`1440×900`、`1024×768`、`390×844`，检查滚动边界、标题稳定、表格折行、图表和构象裁切。
