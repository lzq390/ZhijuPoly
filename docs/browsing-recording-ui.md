# AI 浏览总结界面

记录会话在应用级保存，入口随当前模块和平台导航断点移动。所有模块取消原先主内容前的独占记录行。

## 入口与范围

| 场景 | 桌面入口（≥1024px） | 可开始记录 |
|---|---|---|
| 知识检索 | 当前模式的“准备就绪”右侧 | 仅本地知识库 |
| 数据库筛选 | “数据已就绪”状态右侧 | 是 |
| 其余原生工作台，包括高通量S0–S6 | 公共标题右侧 | 否 |
| 首页通用会话和项目工作区 | 平台侧栏品牌行右侧32px图标 | 否 |
| 实验数据采集和统计 | 共用导航的Collect／Dashboard切换组之后 | 否 |
| 实验流程Demo全部子页 | 共用顶部工具栏Home之后 | 否 |

宽度<1024px时，所有场景只在现有56px平台导航右侧显示40px图标入口。保活但隐藏的页面不渲染入口，移动侧栏不复制入口。

可用入口采用浅蓝至青色渐变底、渐变描边和轻微光感阴影，配合蓝色星芒图标与文字，区别于旁边的白底就绪状态框。悬停加深底色与描边，按下收起外阴影；记录中沿用绿色状态，禁用入口保持中性色。各状态不改变按钮尺寸和位置。

本地知识库记录检索和主动查看的文献、反应信息；数据库筛选记录提交条件、分页和主动展开的详情、结构。数据库查询、在线文献和PDF模式未接入。未接入模块显示禁用开始入口及支持范围，已有会话仍可结束、查看进度、查看总结和重试，并提示“当前页面操作不计入记录”。

## 状态与面板

入口按阶段显示“开始记录”“正在开始…”“结束并总结”“正在结束…”“查看生成进度”“查看总结”或“重试结束记录”。在途操作完成前禁止结束。错误和不完整提示使用状态标记、入口浮层及面板内说明，不撑高页头。开始失败提示仅在失败时自动出现一次，可点击外部、按Escape或失焦收起；错误标记保留，重新悬停或聚焦可查看。再次失败仍会提示，重试沿用原记录ID。

“结束并总结”会冻结采集并生成总结。等待首段内容时显示整理状态；收到正文后逐步显示，保留“正在生成总结，可边生成边阅读”提示。生成完成后按三个自然段展示；空记录直接显示说明，不调用模型。成功后仅在支持采集的页面提供“开始新记录”，位置在面板底部。

流式正文保存在会话 Provider 中，面板收起、切换模块和窗口缩放不会中断请求或清空已生成内容。断流或模型报错时保留未完成正文并提供重试；未完成内容不视为成功结果。重试沿用原记录 ID，清空上次正文后重新生成。

面板在应用级只挂一份，桌面放在当前入口所在标题或状态行下方的主工作区右上角，首页放在主工作区右上方；移动端放在平台导航下方。切页或跨断点切换入口不销毁面板或会话。关闭、Escape和点击外部可收起，生成继续，完成不会自动弹回。关闭后焦点回到当前入口；点击外部按钮或输入框时保留用户选择的焦点，点击标题等非交互区域则恢复入口焦点。Escape优先关闭总结浮层。

总结打开期间，底层详情抽屉暂时释放焦点约束和背景禁用状态，避免跨断点后禁用总结浮层。关闭总结后恢复原抽屉；若移动端模态详情仍打开，焦点优先回到该详情，第二次Escape再关闭详情。

## 实现与验证

- `KnowledgeRecordingProvider` 继续管理会话、在途计数和API；`BrowsingRecordingUIProvider` 管理唯一面板和当前入口引用。
- `BrowsingRecordingControls` 按当前模块和断点选择宿主；`canStart` 仅限制开始新记录。
- `ModulePageHeader.actions` 与标题同行，维持62／84／60px页头及既有滚动规则。知识检索与数据库筛选使用现有状态行，按钮高度36px／2K档54px，与就绪状态对齐。知识检索仅向当前模式传入 `toolbarActions`，保活模式不重复挂载入口。
- 公共记录组件直接加载 `browsing-recording.css`，不依赖知识检索的懒加载顺序。
- `npm run test:recording-browser` 拦截全部API，总结通过本地 HTTP 测试服务真实分块发送，验证冷启动、禁用范围、旧页面宿主、跨页与跨断点生命周期及收起后继续接收正文；不创建真实记录。
- `npm run test:pages` 校验全部原生模块标题几何、滚动、入口唯一和无额外顶部占位。

真实环境验收还需检查运行中后端的 `/openapi.json` 包含三个 `/api/v1/knowledge/recordings` 接口，并从前端完成开始、结束和空记录总结。界面测试使用模拟接口，不能证明当前服务已加载新增路由。GPU 开发会话为保持进程身份而关闭了热重载，同步源码后需通过项目现有会话管理流程更新后端，再验证真实检索和筛选共用记录及 AI 总结；不要只更新前端。

## 流式接口

现有 `POST /api/v1/knowledge/recordings/{recording_id}/summary` 增加内容协商：携带 `Accept: text/event-stream` 时返回 SSE，否则保持原有 JSON 响应。前端仍兼容旧后端返回 JSON，采集事件和最终结果字段不变。

| SSE 事件 | 数据 | 用途 |
|---|---|---|
| `status` | `{"phase":"summarizing"}` | 连接建立，正在生成或等待同一记录的生成完成 |
| `delta` | `{"text":"正文片段"}` | 追加显示正文 |
| `done` | `{"recording_id":"…","summary":"完整正文","generated":true}` | 唯一成功完成标记；空记录的 `generated` 为 `false` |
| `error` | `{"detail":"可读错误"}` | 保留原记录供重试，不缓存半篇正文 |

记录不存在或尚未结束时，仍在发送 SSE 响应头前返回原有 HTTP 错误。响应使用 `Cache-Control: no-cache`、`X-Accel-Buffering: no` 避免中间层缓存/缓冲。后端向现有模型发送 `stream: true`，仅转发正文，不展示思考过程；总生成时限仍为 60 秒。

上游同时显式设置 `stream_options.include_usage: true`。当前中转服务未设置此项时可能省略带 `finish_reason` 的终止帧；设置后保留完整性校验，不将只有 `[DONE]` 的不完整返回认作成功。统计帧不展示给用户。

JSON 与 SSE 共用同一记录锁和完成缓存，重复请求不会并行生成。只有收到上游正常结束及 `[DONE]` 才缓存完整正文；客户端真正断开连接时取消上游生成并释放锁，重试重新生成。关闭面板仅改变显示状态，不会断开连接。已有完成缓存直接返回 `done`。

本次维持 `ASSISTANT_MODEL` 配置和原总结提示词；模型对比参见 [GPT-5.5 与 Luna medium 实测](browsing-summary-model-comparison.md)。会话仍只在当前页面运行期间保留；不增加刷新恢复、历史记录、导出或其他模块的采集能力。
