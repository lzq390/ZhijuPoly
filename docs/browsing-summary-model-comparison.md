# AI 浏览总结模型对比（2026-09-15）

本次在当前开发环境配置的模型中转服务上，用相同浏览证据和现有总结提示词对比 `gpt-5.5` 与 `gpt-5.6-luna`（`reasoning_effort: "medium"`）。Luna 在有查看内容的样本中整篇输出更快，但首次出字没有改善，而且漏掉了文献来源标注。暂时保持当前默认 `gpt-5.5`，先上线流式显示。

## 方法与边界

- 基线使用当前 `ASSISTANT_MODEL=gpt-5.5`；与应用一致，不传 `reasoning_effort`，采用中转服务默认行为。不能据此断言服务内部采用哪个推理档位。
- 候选请求明确传入 `model: "gpt-5.6-luna"`、`reasoning_effort: "medium"`。服务返回的模型名与请求一致。官方文档列明该模型支持流式和 medium 档位；这里的耗时是当前中转路径的实测，并非官方直连基准。[模型文档](https://developers.openai.com/api/docs/models/gpt-5.6-luna)
- 两者均使用 Chat Completions、`stream: true`、`stream_options.include_usage: true`、相同系统提示词和相同输入 JSON。首字耗时从发送请求计至首个非空正文片段，完成耗时计至 `[DONE]`；不把状态事件或推理片段算成首字。
- 两类输入，各模型每类重复两次，共 8 次请求。每轮交替模型顺序，顺序执行。所有请求 HTTP 200、正常结束，无截断。样本小且存在网络/服务排队波动，不适合据此承诺固定延迟或推算 p95。
- 输入由真实知识库和筛选接口采集：检索 `polyimide`，筛选标准化 Tg 下限 100；“已查看”样本另包含文献 #17525 的标题与摘要，以及材料记录 76126 的 Tg 345.15 °C。两者没有来源对应证据。筛选请求未传单位，检索样本因此也检查模型是否擅自补单位；展开的测量记录有明确 °C 单位。

## 内容检查

| 检查项 | GPT-5.5 | Luna medium |
|---|---|---|
| 未打开详情时是否编造具体文献结论 | 两次均未编造具体文献结论 | 两次均未编造具体文献结论 |
| 已查看的 Tg 数值与单位 | 两次均保留 345.15 °C | 两次均保留 345.15 °C |
| 是否将材料测量与文献当成同一实验 | 两次均明确无法直接对应 | 两次均明确无法直接对应 |
| 文献来源标注 | 两次均保留 `[文献 #17525]` | 两次均遗漏 |
| 材料来源标注 | 两次均遗漏 `[材料 #1]` | 两次均遗漏 `[材料 #1]` |
| 仅检索样本的缺失单位 | 一次擅自写成 100 °C，并同时声称未提供单位 | 一次不补单位，一次明确指出单位未采集 |
| 提示词“不要列操作和结果数量” | 未列具体命中数量 | 一次列出 3949 和 14598 条结果 |

两者都有提示词遵循问题，均需更大样本检查；不能将本轮结果视为 GPT-5.5 已完全合格。当前更有依据的选择是保留基线并先改善交互。如后续切换 Luna，应先解决来源标注与事实边界问题，再扩展多文献、多属性、缺失单位和长记录样本评估。
