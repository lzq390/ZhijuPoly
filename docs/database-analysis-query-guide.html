02连接数据库

先在终端设置上面的非敏感连接参数；下面的 -W 会交互式提示数据库口令。不要把口令写入命令、文档或版本库。

psql -X -h "$DB_HOST" -p "$DB_PORT" \
  -U "$READONLY_USER" -d "$DB_NAME" -W -v ON_ERROR_STOP=1

进入 psql 后确认目标，并限制当前会话的操作与单条语句时长：

SELECT current_database() AS database_name,
       current_user AS database_user;

SET default_transaction_read_only = on;
SET statement_timeout = '15s';

只读会话设置不替代账号权限。图形工具使用相同的管理员授权参数，在 SQL 编辑器中执行后续查询；新建连接后需重新设置会话选项。如需 SSH 隧道，使用管理员批准的已有接入配置。

04

查看表与字段

在 psql 中查看

下面以反斜杠开头的命令只用于 psql，逐条输入即可：

psql · 客户端命令
\conninfo
\dt experimental.*
\dt core.*
\dt dft.*
\dt knowledge.*

\d experimental.process_records
\d experimental.property_records
\d core.polymer_properties
\d core.polymers
\d dft.molecule_final
\d dft.energy_trace
\d knowledge.formulation_records

\dt 列出表，\d 查看字段、类型、主键、索引和外键。查询结果进入分页器时，按 q 返回；也可先执行 \pset pager off 关闭分页器。

在 SQL 编辑器中查看

下列 SQL 同样适用于 psql。修改 schema 和表名即可查看其他表：

psql 或 SQL 编辑器 · SQL
SELECT ordinal_position, column_name, data_type, is_nullable
FROM information_schema.columns
WHERE table_schema = 'experimental'
  AND table_name = 'process_records'
ORDER BY ordinal_position;
05

查询原始数据

本节全部是 SQL，可在 psql 或图形工具 SQL 编辑器执行。预览默认取 20 条；文本预览截取前 200 个字符，查完整记录时按对应主键筛选。

5.1 实验过程数据

查看材料名称、产品名称、过程文本和原始来源位置：

SQL · 过程记录预览
SELECT record_id, polymer_id, polymer_name, product_name,
       left(process_flow_original_text, 200) AS process_preview,
       left(material_original_text, 200) AS material_preview,
       source_file, source_row_number
FROM experimental.process_records
ORDER BY record_id
LIMIT 20;
查看一条完整记录与原始 JSON

以下自动取第一条记录；查指定记录时，把子查询替换为预览结果里的实际 record_id。

SQL · 完整过程记录
SELECT record_id, process_flow_original_text,
       material_original_text, jsonb_pretty(raw_data) AS raw_json
FROM experimental.process_records
WHERE record_id = (
  SELECT record_id FROM experimental.process_records
  ORDER BY record_id LIMIT 1
);

5.2 实验性能数据

查看性能类别、属性英文名和原始性能值：

SQL · 性能记录预览
SELECT record_id, polymer_id, polymer_name,
       property_category, property_name_en, value,
       source_file, source_row_number
FROM experimental.property_records
ORDER BY record_id
LIMIT 20;
查看库里有哪些性能类别和属性
SQL · 性能类别统计
SELECT property_category, property_name_en,
       count(*) AS record_count
FROM experimental.property_records
GROUP BY property_category, property_name_en
ORDER BY record_count DESC, property_name_en
LIMIT 20;

value 是文本字段，可能包含单位或其他描述。需要数值区间查询时，使用结构–性能表中的 property_value_num，并核对属性和单位。

5.3 结构–性能数据

性质和 SMILES 分别存放在两张表中，用 polymer_id 关联后查看：

SQL · 结构与性能关联查询
SELECT p.property_id, p.polymer_id,
       s.smiles, s.canonical_smiles,
       p.property_category, p.property_name,
       p.property_value, p.property_value_num,
       p.property_unit, p.label_source
FROM core.polymer_properties AS p
JOIN core.polymers AS s ON s.polymer_id = p.polymer_id
ORDER BY p.property_id
LIMIT 20;
按属性和单位查看数值范围
SQL · 数值性能范围
SELECT property_name, property_unit,
       count(*) AS numeric_records,
       min(property_value_num) AS minimum,
       max(property_value_num) AS maximum
FROM core.polymer_properties
WHERE property_value_num IS NOT NULL
GROUP BY property_name, property_unit
ORDER BY numeric_records DESC, property_name, property_unit
LIMIT 20;

做条件筛选时，在 WHERE 中同时限定实际属性名、单位与数值范围；同一属性的不同单位应分别处理。

5.4 DFT 构象与优化轨迹

molecule_final 每个分子一条最终结果；energy_trace 每个优化步骤一条记录。

SQL · 最终构象结果
SELECT mol_id, range_group, final_step, n_atoms,
       scf_energy, homo_ev, lumo_ev, gap_ev, is_converged,
       pca_x, pca_y, pca_z
FROM dft.molecule_final
ORDER BY mol_id
LIMIT 20;

以下自动取第一个分子的完整优化轨迹。查看指定分子时，将括号内的子查询替换为实际分子编号字符串，例如 WHERE mol_id = '实际编号'。

SQL · 单个分子的优化步骤
SELECT mol_id, step, scf_energy, homo_ev, lumo_ev, gap_ev
FROM dft.energy_trace
WHERE mol_id = (
  SELECT mol_id FROM dft.molecule_final
  ORDER BY mol_id LIMIT 1
)
ORDER BY step;

原子坐标在 dft.molecule_final.coordinates 字段。网页上的三维构象展示可通过第 7 步的 DFT 页面查看。

5.5 配方比例与来源文档

查看配方文本、催化剂、温度、反应时间、溶剂，并关联来源文档标题：

SQL · 配方与来源文档关联查询
SELECT f.formulation_id, f.knowledge_id, f.polymer_iupac,
       f.formulation, f.catalyst, f.temperature,
       f.reaction_time, f.solvent,
       f.source_file, f.source_row_number,
       d.title_zh, d.title_en
FROM knowledge.formulation_records AS f
JOIN knowledge.documents AS d ON d.knowledge_id = f.knowledge_id
ORDER BY f.formulation_id
LIMIT 20;

formulation 保留配方文本。完整摘要、权利要求等来源内容可通过同一 knowledge_id 查询 knowledge.documents。

06

统计、分页与导出

实时核对各表记录数

SQL · 表记录数
SELECT 'experimental.process_records' AS table_name,
       count(*) AS record_count FROM experimental.process_records
UNION ALL
SELECT 'experimental.property_records', count(*)
FROM experimental.property_records
UNION ALL
SELECT 'core.polymer_properties', count(*) FROM core.polymer_properties
UNION ALL
SELECT 'core.polymers', count(*) FROM core.polymers
UNION ALL
SELECT 'dft.molecule_final', count(*) FROM dft.molecule_final
UNION ALL
SELECT 'dft.energy_trace', count(*) FROM dft.energy_trace
UNION ALL
SELECT 'knowledge.formulation_records', count(*)
FROM knowledge.formulation_records
ORDER BY table_name;

条件筛选与分页

将下面的“关键词”替换为材料名或产品名的一部分。ILIKE 用于不区分大小写的文本匹配；% 表示任意文本。

SQL · 关键词筛选与分页
SELECT record_id, polymer_name, product_name
FROM experimental.process_records
WHERE polymer_name ILIKE '%关键词%'
   OR product_name ILIKE '%关键词%'
ORDER BY record_id
LIMIT 20 OFFSET 0;

第 1 页用 OFFSET 0，第 2 页用 OFFSET 20。连续翻看大量记录时，可使用上一页最后一个 record_id 作为下一页条件：

SQL · 根据上一页最后一条记录继续查询
SELECT record_id, polymer_name, product_name
FROM experimental.process_records
WHERE record_id > 0 -- 将 0 替换为上一页最后一个 record_id
ORDER BY record_id
LIMIT 20;

如果上一页使用了关键词等筛选条件，下一页也应保留相同条件。

导出 CSV 到客户端当前目录

先用 \q 退出 psql，再在服务器终端执行。下面导出前 1,000 条过程记录，文件由终端重定向写入运行客户端的当前目录。

客户端终端 · Shell · 导出 CSV
PGOPTIONS='-c default_transaction_read_only=on -c statement_timeout=15000' \
psql -X -h "$DB_HOST" -p "$DB_PORT" \
  -U "$READONLY_USER" -d "$DB_NAME" -W -v ON_ERROR_STOP=1 \
  -c "COPY (
    SELECT record_id, polymer_name, product_name, source_file
    FROM experimental.process_records
    ORDER BY record_id
    LIMIT 1000
  ) TO STDOUT WITH (FORMAT csv, HEADER true, ENCODING 'UTF8')" \
  > experimental-process-preview.csv

使用 DBeaver / pgAdmin 时，可在查询结果网格中选择导出 CSV；文件保存在运行客户端的电脑上。

查看页面统计更新时间

页面图表的汇总统计存放在 governance.database_analytics_snapshots。第 5–6 步直接查询业务表中的原始数据。

SQL · 页面统计快照与北京时间
SELECT snapshot_key,
       generated_at AT TIME ZONE 'Asia/Shanghai' AS generated_at_beijing,
       datasets -> 'process' ->> 'rows' AS process_rows,
       datasets -> 'property' ->> 'rows' AS property_rows,
       datasets -> 'structureEffect' ->> 'rows' AS structure_property_rows,
       datasets -> 'dft' ->> 'rows' AS dft_step_rows,
       datasets -> 'dft' ->> 'molCount' AS dft_molecules,
       datasets -> 'formulation' ->> 'rows' AS formulation_rows
FROM governance.database_analytics_snapshots
WHERE snapshot_key = 'database-browser';

DFT 的 rows 对应优化步骤数，molCount 对应分子数。核对页面记录量时应分别比较。

08常见问题

  • 连接失败：核对管理员提供的 DB_HOST、DB_PORT、DB_NAME 和既有接入方式。
  • 认证失败：核对专用只读账号；SSH 认证和数据库认证分别用于各自连接。
  • 表不存在：确认 current_database()，并使用完整 schema.表名。
  • 权限不足：联系管理员确认账号既有授权，不在查询指南中修改权限。
  • SQL 编辑器不支持反斜杠命令：使用第 4 节的 information_schema 查询。
  • 查询超时：优先缩小范围、按主键筛选；本文示例不声明当前库的行数或运行性能。
  • 页面与原始表统计不同：核对环境、快照时间和统计口径，区分 DFT 分子数与优化步骤数。

完成后在 psql 输入 \q 退出；图形工具按其连接管理方式断开。
