# 组件化画板加载优化：Ketcher 3.8.0 / NexPoly r4

本轮保留原生组件画板和业务源码 HMR，将 SDK 改为独立的生产构建，并把 Worker 启动移到画板深链的 HTML 入口。小分子首屏不再创建隐藏的 Macro 编辑器。9000 保持只读，候选在独立实例验证。

本次优化沿用 iframe 的独立资源与启动思路，但保留组件化接入。收益来自减少 SDK 首屏工作量、提前启动 Worker，并让业务加载与化学服务准备并行；不把秒级收益归因于容器从 iframe 变成 div，也不删除文档正确性检查。

**正式性能验收通过：六个入口的 36 个场景及主工作台独立确认，UI 就绪和首次真实导出完成的 P50、P95 均快于同批 9000。** 主矩阵 2160 个样本、独立确认 360 个样本，均无失败。代码在全部门槛通过后提交；实际 9001 的重启及部署后验证记录位于下文交付回执。

## 基线与测量口径

业务基线固定为 `ca8118b23d61031a1bde85b5bbe8fd14967fe14f`。实施期间其他任务提交的业务改动已经纳入基线；优化在 `codex/ketcher-loading-r4` 独立工作树开发。锁文件不变，SDK 从 `nexpoly-3.8.0-r3` 升为 r4，Ketcher 仍为 3.8.0。

9000 为实际运行的 Ketcher 3.7 iframe，镜像及静态资源摘要单独冻结。历史 Chrome 151 的样本仅用于解释优化方向；本轮固定 Chromium 153.0.8010.12、1440×900、878×566 实际 SVG 画布、正常动画，用同批交替样本比较。候选与同源码 r3 基线都使用实际 9001 的 Node 容器镜像和公开环境配置，包含两版都会加载的外部工作台。最终 SDK 内容版本为 `9f4e0f5f5b6efd35fb6b`。

- 六个入口：结构工作台、数据库查询、相似性探索、均聚物预测、条件生成、逆向设计。
- 每个版本、入口、轮次使用全新的持久化浏览器配置。依次测冷访问、普通刷新、禁用 HTTP 缓存刷新；禁缓存仍保留该进程的代码缓存，和全新配置的冷访问分别报告。
- 本机与模拟远程分别测量。远程条件为 40ms 延迟、50Mbps 下载、10Mbps 上传，不设置 CPU 降速。远程场景使用实际 HTTP 9001 浏览器会发送的 `gzip, deflate` 协商头；本机保留浏览器默认 Brotli 协商。两版使用同一设备，逐样本记录主机负载，不并行运行构建或其他浏览器回归。
- UI 就绪要求实际 SVG 画布可见、公共清空按钮可用，原生版本还要求共享工作区为 `ready`；随后立即调用实际 `getSmiles()`，记录首次导出完成。
- 每个性能样本随后导入 CCO、用鼠标拖动氧原子、确认 KET 坐标改变、导出 CCO、公共清空并确认空导出。API 请求不拦截，不创建计算任务。
- 保留失败、慢样本、请求、长任务和阶段标记。P50/P95 使用最近秩；按同入口、网络、缓存和轮次配对，提供差值和中位差值的 bootstrap 95% 区间。失败按无穷耗时参与验收，不删除后重算。
- CDP 未提供外置 Worker 的完成字节时，补充浏览器 ResourceTiming 的 `transferSize`，标明其头部估算。避免沿用会漏算外置 Worker 的早期冷传输探针。传输统计为首次导出后的就绪快照中已完成的 HTTP 资源，区分同源与全部来源；外部工作台和字体可能仍在加载，不能称为完整导航的最终总量。

筛选阶段每场景 10 对；最终每场景 30 对，主工作台另做独立确认批次。隔离上下文的功能与资源故障测试单列，不能替代持久化缓存性能样本。

## 启动与交付边界

```text
画板深链 HTML
  ├─ 预加载轻量业务入口和当前页面根模块
  ├─ 加载独立生产 SDK 的小分子静态依赖与样式
  └─ 轻启动入口创建 Worker，执行真实 Info
                    ↓
可见画板的 createStructService 原子接管该 transport
                    ↓
2D 与 Info 完成 → 启动导入 → 共享文档恢复与原有提交检查
                    ↓
公共工具与实际导出可用
```

`shared/canvas-routes.ts` 是业务路由与 HTML 判断的共同来源。普通页面首次进入不加载原生 SDK、不创建 Worker。页面内导航只提前获取代码，并沿用保存、过渡和取消事务；已有会话持有 Worker 时不另建预热 Worker。

`sdk/bootstrap.mjs` 仅依赖通信层，不静态引入 React 或 Core。`sdk/micro.tsx` 使用匹配的生产 React/ReactDOM，向宿主提供 `mount(container, options)` 和幂等 `dispose()`。宿主仍使用 Vite 的开发 React，双方只传 DOM、普通配置、回调和编辑器句柄，不跨 React root 传组件或 Context。

预热租约为 `prepared → claimed → disposed`。接管发生在实际服务创建处，先检查会话，再同步转移同一 Worker、监听器、队列和 Info Promise。未接管时，导航、失败、HMR、页面退出或 15 秒期限负责销毁；接管后由 `NativeEditorSession` 独占，销毁后不回池。每个正常刷新只创建一个 Worker。

Worker 是从上游实际 Blob 内容逐字节提取的外置文件，SHA-256 为 `410080855a8dc69cf25b6854dbd8ac1c96c4ab10c67c17affc2cde1bfc736f8e`。内部 WASM 和命令协议不变。主线程 SDK 不再携带、解析或解码大型 Worker Base64 字符串。

独立构建检查启动入口的静态依赖不含 React/Core，小分子静态依赖不含 Macro UI。Macro 专属 JavaScript 合为一个按需块，只依赖已经成功加载的共享块；CSS 单独按需获取。现有弹窗归属、键盘隔离、CSS 作用域和销毁修复继续生效。

## Macro 与文档正确性

新增 `Editor.deferMacromoleculesEditor?: boolean`，SDK 默认关闭，产品入口开启。`ensureMacroReady(): Promise<void>` 只准备能力，不切换可见模式，也不把新建的空 Macro 写回已有小分子文档。

首次切换、SDK 导入、文件窗口、formatter、宏格式导出、单体和库入口共用能力检查。`setMolecule/addFragment` 接受可选 `inputFormat`；文件窗口保留明确格式，KET 检查节点及模板中的宏实体。明确 HELM/FASTA 等先规范化为 KET；需要进一步判断的格式只在实际导入时规范化。含糊的裸文本保留原有识别语义。

导入与模式切换使用同一队列。`switchToMacromoleculesMode()` 和 `switchToMoleculesMode()` 返回 Promise，在模型转换和带命令编号的 React 界面提交确认后完成。因此直接 HELM 导入后切回小分子、并发切换，以及可见模式未改变但模型所有权改变，都能正常结束。导出读取实际持有结构的模型，formatter 保留调用方的结构、选择区和绘图管理器。

Macro 初始化有 15 秒超时和代次标识。失败保留小分子画板，提供显式重试；失败的专属模块使用新请求标识，已经成功的代码继续复用。退役拒绝等待操作，清理部分实例，并阻止迟到结果写入新会话。同步 API 继续同步；使用需要 Macro 的同步入口前，调用方先等待 `ensureMacroReady()`。

SDK 的 `onInit` 等待真实 2D、Info 和已声明的 URL 初始导入，每个实例只通知一次。共享工作区仅在文档和草稿均未被修改时接纳 URL 导入，然后执行原有恢复和正确性检查；异步期间的新编辑具有优先权。整页刷新仍不假设自动持久化结构。

本轮保留原有约 160ms 提交等待、KET 校验、版本竞争保护和 ready 后居中。空白初始化改用正常空 KET 提交，减少无意义的空 SMILES Worker 转换，没有提前宣告 ready。

回归还定位并修复了 Redux 记忆缓存经旧服务持有 Macro controller、进而保留退役 SDK 的引用链；实际服务能在 onInit 前取消 controller，退役清除文档及 React 回调引用。开发和生产的十次重挂载弱引用检查均通过。

## 构建、缓存、重试与维护

`npm ci` 应用四包补丁并校验版本、16 个 SDK 文件、四个补丁及可读源码片段。补丁覆盖 ESM/CJS、React 内置 Macro 与独立 Macro、类型声明。正常构建前再次验证，失败即停止，不通过修改摘要绕过错误。

开发服务和正式构建先生成或验证 `.ketcher-runtime/<版本>/`。缓存依据锁文件、补丁、SDK 构建输入、样式处理及被验证的安装内容失效。清单记录角色、大小、摘要、依赖图和补丁版本；构建先写临时目录，验证后原子切换，并检查并发构建结果一致。iframe 构建不生成、输出或请求原生 SDK 制品。

SDK、Worker 和样式使用内容版本地址，并生成 gzip/Brotli 文件。开发中间件实现压缩协商、MIME、Vary、ETag、HEAD/304、长期缓存和明确的缺失响应；生产 nginx 使用 gzip_static。业务源码、API 与 HMR 沿用既有链路。

SDK 资源失败可通过新模块命名空间重试，避免浏览器重复命中失败模块；Macro 使用专属重试编号。首次 SDK 的代码、样式及启动模块同样有 12 秒资源超时，早于会话的 15 秒期限；超时取消待加载样式和预热租约，重试使用新的资源命名空间。HTML 启动入口响应导航和失败取消，迟到模块不再重新创建 Worker。旧版本制品继续可访问，避免开发重建让尚未退出的会话失去资源。业务 HMR 保留实例和结构；SDK 重建后完整刷新画板，禁止新旧 SDK 在同一会话混用。

维护 r4 时，可读片段位于 `frontend/sdk/`，对应内容必须同步到版本化补丁的 ESM/CJS 副本。更新后从干净 npm 制品生成补丁，保留上游摘要，更新审核后的补丁和安装内容摘要，再正常安装验证。Standalone 补丁使用两行上下文，避免把未改变的巨型 Base64 行纳入补丁。上游 CRLF 和补丁空白上下文保留原字节，以摘要及干净重放验证。

独立启动层、小分子桥接层等正常 SDK 源码修改会重建制品；嵌入 vendor 的片段修改须先同步补丁，校验会阻止只有片段变化的半成品进入运行环境。

## 回滚边界

9000 全程只读。9001 更新前保留 ca8118 基线快照、r3 补丁与锁文件；需要回滚时恢复该版前端输入，正常安装 r3，重启开发前端服务。不要仅替换构建目录而保留不匹配的 SDK 补丁或宿主代码。现有 iframe 引擎仍可通过构建参数选择，但组件版本回滚应使用保留的上一版组件快照。
