# 9003 当前服务器监测

当前实现只观察本宿主机：CPU、内存、负载、运行时间、`/` 与 `/data` 文件系统，以及全部物理 NVIDIA GPU。采集器不导入科研后端，不分配 GPU，不调用 Broker、MPS、Worker 或服务恢复接口。

浏览器通过 9003 同源代理访问独立监控 API；监控 API 每次向已有开发后端验证真实会话。只有 `zhiju000`、`zhiju001`、`zhiju002` 的用户名与 UUID 配对可读取指标，授权与会员等级无关。

## 数据链路

```text
host /proc + statvfs + fixed nvidia-smi query
    -> collector (5 s)
    -> private atomic latest.json / history.json
    -> 127.0.0.1:5319 read-only API
    -> 9003 /api/v1/server-monitoring/*

local retained DFT journals + read-only MD database projection
    -> independent history reader (60 s)
fixed compute-apps query + verified live process identities
    -> GPU activity reader (5 s, same dedicated process)
    -> private atomic gpu-tasks.json
    -> same authenticated read-only API

9003 other /api/* -> 127.0.0.1:18000 (real development backend)
```

GPU 查询设 3 秒超时并清理继承环境，使用 UUID 识别显卡。CPU 使用相邻 `/proc/stat` 差值；首次读取及长时间采样中断后显示待采集。内存使用 `MemTotal - MemAvailable`。磁盘百分比按 `used / (used + available)` 计算，与普通用户的文件系统可用空间口径一致；保留总量、已用量和可用量。

快照可选字段 `host_info` 提供 CPU 型号、物理插槽与核心数量、操作系统名称、内核和 NVIDIA 驱动版本。采集器启动时读取固定的 `/proc/cpuinfo`、`/etc/os-release`、`/proc/sys/kernel/osrelease` 和 `/proc/driver/nvidia/version`，随后每小时刷新缓存；不额外调用 GPU 查询、不执行系统配置文件。各字段独立允许为空，缺失显示 `--`，不会阻断实时指标。旧快照没有该字段时仍可读取。

当前值每 5 秒采集；每 30 秒汇总有效样本均值，历史最多保留 120 点。空缺保持空值，浏览器不会补零。历史文件在页面刷新后保留；采集器重启后开始新的历史区间，前端清除旧采集实例的数据。

时钟回拨时重新建立 CPU 基线并清空历史；长时间中断后仅保留真实最近一小时内的点。接口保留本次采集的实际起点；图表使用真实时间，不将未观测到的时间补成零值。

快照超过 15 秒显示过期，超过 60 秒显示采集不可用。这些状态不代表物理服务器已经关机。GPU 采集失败不阻断 CPU、内存和磁盘采集。

## 准备与启动

在本功能工作区根目录运行。以下命令只建立独立运行环境和四个专用用户服务，不运行常规 `dev_server_gpu.sh`，不重建 `nexpoly_dev` 项目。

```bash

.runtime/server-monitoring-9003/venv/bin/pip install --require-hashes -r server_monitoring/requirements.lock
# 前端依赖使用项目已有 package-lock.json 和正常安装流程。

  --node /home/devuser/.nvm/versions/node/v22.23.2/bin/node

```

`prepare` 通过现有 `nexpoly_dev-backend-1` 进行一次只读账号查询，将三个有效账号的 UUID 固定到私有配置；缺失、停用或要求修改初始密码的账号会使准备失败。运行时 API 不连接数据库，只调用固定的真实认证端点。

前端使用 Vite 7，需要 Node 20.19+ 或 22.12+。当前机器的 `/usr/bin/node` 为旧版本，因此上述命令明确指定已有的 Node 22；脚本会先检查版本，不会让不兼容的预览进程进入重启循环。

私有运行目录为当前工作区的 `.runtime/server-monitoring-9003/`；配置及快照为当前用户所有的私有普通文件，不能放入 Git。目录中包含独立虚拟环境、`config.json`、`state/`、验收产物与回退信息。

服务名称：

- `nexpoly-server-monitoring-task-history.service`
- `nexpoly-server-monitoring-api.service`

服务通过用户 systemd 启动，未设置开机自动启用。机器重启后可再次运行 `start` 和 `preview`。工作区必须保留，不应在这些服务运行时删除或归档。

## 接口与故障表现

四个接口均为 GET，前缀为 `/api/v1/server-monitoring`：`/access`、`/snapshot`、`/history`、`/gpu-tasks`。所有接口都先验证真实会话；`/access` 只决定界面入口，不替代数据接口授权。会员等级例外仅适用于这四个精确 GET 路径。

错误码区分未登录（401）、无权访问（403）、会话变化（409）、认证不可用或指标不可用（503）。认证错误会隐藏页面已有指标及任务记录；采集错误则显示明确的错误和最后有效采样时间。响应禁止缓存，不包含 Cookie、CSRF token、进程命令行、任务所属用户、任务输入或计算结果。

页面可见时每 5 秒请求最新值、每 30 秒请求历史；页面隐藏暂停，恢复后立即读取。多个浏览器共享一个采集器，手动刷新不会额外启动 GPU 查询。

## GPU 当前活动与完成任务

GPU 任务卡分为“当前正在进行”和“近期完成任务”。当前活动使用固定的 `nvidia-smi` 计算进程查询获得物理 GPU UUID 和进程显存用量，再只读核对本机进程身份及平台运行记录。采集结果区分计算任务、常驻服务和仅检测到的 GPU 进程；“当前正在进行”只展示 `kind=task` 且 `status=running` 的已确认任务，隐藏常驻服务及未确认归属的进程。模型驻留显存不等于正在执行计算；进程消失不会被推断为任务成功完成。

当前活动每 5 秒读取，查询设超时且不重叠。原资源指标采集器保持独立；浏览器数量不会增加上述固定查询频率。输出只有安全的服务／模块名称、运行类别、开发／生产来源、显存观测和时间，不返回 PID、命令行、用户或控制令牌。

独立读取器每 60 秒扫描本机两个固定目录中的 DFT Worker 日志：

- 开发：`/data/lzq/gith/nexpoly-dev/.runtime/monomer-dft-worker-runs/*/*/journal.json`
- 生产：`/data/lzq/gith/nexpoly-runtime/state/monomer-dft-worker-runs/*/*/journal.json`
- 生产当前服务：`/data/lzq/gith/nexpoly-runtime/state/p9000-20261102r2/dft/jobs/*/*/journal.json`；与前一目录按来源和任务标识去重。

只读取已保留、已完成、具有可核验实际执行 GPU UUID 的 DFT 记录。记录须满足受支持的日志版本、执行路径、Worker 身份和实际执行元数据校验；GPU UUID 及物理编号必须与当前宿主机快照一致。不会根据 CUDA 局部编号、用户个人任务列表或 Worker 的配置猜测执行显卡。目录为本机可信来源；旧日志没有独立宿主机 ID，因此归属验证依赖固定本机目录及实际 GPU UUID。

单体 MD 的完整完成状态和起止时间来自现有开发／生产应用库的固定只读投影；实际 GPU UUID、Worker 与 Broker 执行证据须一并通过校验。正式计算与演示计算分别标注。查询使用已有后端容器内的数据库驱动，固定容器和 SQL，只读事务及连接／语句／进程超时，不加载业务应用、不进行数据库迁移，也不把数据库凭据输出到主机快照或页面。当前聚合物 MD 执行器未启用 GPU，保留记录也没有实际 GPU UUID，因此只计入排除统计，暂不支持按 GPU 展示其完成历史。参数中的 `gpu=0` 是 GPU 数量标志，不能当作物理 GPU 0。

读取范围和文件大小有上限，拒绝符号链接及异常文件。原始日志中的用户、输入、分子、结果、路径及租约信息不会进入监控快照。完成记录仅返回散列任务标识、模块及计算类型、开发／生产来源、完成状态、开始／完成时间、耗时及 GPU UUID；每张显卡按真实完成时间混合保留最近 10 条，页面只展示最近两条，不按服务类型补位或提供类型筛选。它不调用 Broker、Worker API，不启动计算任务，也不操作生产服务。

这不是完整任务审计：已清理日志、缺少可验证 GPU 归属的旧记录，以及没有保存执行审计的其他服务调用无法事后还原。成功读取且无匹配记录时显示“暂无可关联的历史记录”，不能理解为该 GPU 从未执行任务。来源缺失、损坏或读取受限时，接口仍保留真实状态；页面静默沿用最近完整成功的结果，不显示普通读取／校验异常横幅或重试按钮。没有可用记录或无法确认空结果时显示 `--`。当前活动与完成历史分别保留，失败的一组不会清掉另一组。

独立任务读取器将最近成功的两组数据原子保存到固定私有文件 `gpu-tasks-last-good.json`，包含成功的空列表。仅恢复通过原有严格结构、文件权限、节点和完整 GPU UUID 集合校验的缓存；设备集合变化或时钟回拨产生未来记录时清除对应缓存。部分失败／不可用结果不会覆盖完整成功缓存，恢复成功后自动更新。回退保留原活动和历史采样时间，接口将回退组标为 `partial` 并保留错误码，不将旧结果重新标记为实时成功；缓存活动在页面仅使用“最近运行任务”小标签。新增文件不包含用户身份或原始任务内容，不增加 GPU 查询频率。

任务快照每 5 秒更新当前活动，超过 15 秒为过期、超过 60 秒为不可用；完成历史每 60 秒读取并缓存，独立使用 90／180 秒阈值。这些内部状态不会触发普通任务提示横幅。浏览器可见时按请求完成后 5 秒轮询，网络失败保留当前会话最近成功的各组结果并后台重试；切换 GPU 只筛选同一缓存。隐藏、退出或切换账号时取消请求，身份失效清空记录及浏览器回退缓存。仅任务接口的认证失败保留权限提示及“重新读取”入口，重新通过真实鉴权后恢复；旧账号的回调和数据均不会被恢复。

## 页面布局

页面使用系统总览／实验工具共用的网格渐层背景、标题间距、蓝青配色和白色卡片。卡片支持悬停、选中提示、键盘焦点及减少动画偏好。常态界面不展示采样频率、最近观测、历史扫描及采集起点等实现说明；异常或数据过期时仍显示必要提示，避免将旧数据视为实时状态。

字体使用平台共用字体，监控局部统一为 24px 页面标题、14px 区块及资源卡标题、12px 正文与控件、11px 辅助文字、22px 主要数值；字重和行高按同类信息统一。控件默认高 34px，触屏使用 40px，六项参数说明仍保持一行。

顶部仅保留服务器切换，本期只有当前宿主机。服务器卡片展示 CPU、1 分钟负载、内存和系统盘四条进度条。第二部分标题为“服务器详情”，左侧使用紧凑的三列两行参数布局，依次展示 CPU、内存、系统盘、数据盘、负载和 GPU 总显存占用；各项仅保留一行说明，容量展示已用与总量。GPU 总显存按全部物理显卡的实际显存加总，任一所需字段缺失时不将其当作零。正常监测状态统一显示“在线”；异常状态继续依据真实采样结果展示。

详情右侧为“主机信息”，使用本宿主机的监控快照展示 CPU 型号与拓扑、操作系统与内核、NVIDIA 驱动，以及系统盘／数据盘可用容量。型号和版本不硬编码，长文本保留完整提示，未知字段显示 `--`。磁盘可用容量沿用 `f_bavail`，不从总量减已用量推算；不再重复展示内存与汇总显存余量，不请求个人任务接口。

第三部分将全部 GPU 卡片排成一行，每张卡展示利用率、显存、温度和功耗，底部显示实际显存用量与总量。切换显卡仅更新设备选择，保留当前趋势指标：CPU／内存、GPU 利用率或 GPU 显存都不会自动跳转。服务器参数区保持显示整机数据；点击当前服务器卡片恢复 CPU 与内存趋势。页面不再设置单独的底部存储空间或采样状态区块，分项故障及最后成功时间集中显示在异常提示中。

下方左侧为“GPU 任务”，桌面约占 28%（最小 280px），其余宽度用于资源趋势，两张卡片保持同高。单卡模式显示该 GPU 已确认的运行任务和最近两条完成记录；默认及“全部 GPU”模式显示所有 GPU 已确认的运行任务，并按全局真实完成时间取最近两条，不按显卡或服务分配名额。汇总记录上的 GPU 编号可点击，联动卡片、任务和趋势显卡；单卡任务标题右侧的返回按钮恢复全部 GPU，两种操作均保留当前趋势指标。无法映射到当前设备的记录显示不可点击的“历史 GPU”。切换使用同一份缓存，不额外触发采集或重挂任务请求。小屏幕改为纵向排列。

趋势图支持鼠标悬停、触屏轻点及键盘方向键／Home／End 读取真实采样时间和当前指标；Escape 关闭读数。切换 GPU 或指标后读数同步更新；未知值显示 `--`，缺口仍保持断线，不补零或插值。触屏滑动继续滚动页面。图表按实际容器宽度重新绘制，手机端保留坐标字号和绘图区高度。

GPU 趋势筛选复用总览使用的 `WorkbenchSelect`。收起时显示“全部 GPU”或显卡编号，展开后显示真实型号、显存容量和选中标记，支持方向键、Home／End、Enter、Escape 和外部点击关闭。菜单在滚动区域内自动选择展开方向，置于趋势图与标签上方；硬件列表变化时关闭旧菜单，按最新物理 GPU UUID 同步卡片、趋势和任务。

负载条按逻辑 CPU 数归一化。温度条使用 0–100 °C、功耗条使用 0–500 W 的展示刻度，实际数值不截断，展示刻度不代表设备限制；条目提示及无障碍描述中有相应说明。

进度条按归一化数值使用经典绿黄红：低于 60% 为绿，60% 至不足 85% 为黄，85% 及以上为红，缺失值为灰。颜色用于辅助判断数值程度，实际数值和文字同时保留。

页面标题固定，内容区域可纵向滚动。桌面 GPU 四卡同排，窄屏采用可触控横滑的卡条；参数和趋势按纵向页面浏览。真实浏览器验收包含桌面和手机尺寸的滚动到底、卡片选择与趋势联动。

## 验收

自动化测试在 `server_monitoring/tests/` 和前端监控模块附近，覆盖真实会话契约、权限拒绝、文件损坏、指标异常、历史边界、账号切换和页面可见性。

一小时持续验证脚本只使用由真实登录获得的私有 session 文件，不创建模拟账号或伪造 Cookie：

```bash
python3 scripts/verify_server_monitoring_live.py \
  --base-url http://127.0.0.1:9003 \
  --session-file .runtime/server-monitoring-9003/zhiju000-session.json \
  --output-dir .runtime/server-monitoring-9003/artifacts/soak \
  --duration-seconds 3600
```
