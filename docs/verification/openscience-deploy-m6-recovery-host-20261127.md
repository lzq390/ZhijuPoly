2026 年 11 月 27 日，运维指定第二台恢复候选后，已通过原有 SSH 主机密钥及部署账号登录。源机和目的机均未检测到虚拟化，机器标识、启动实例和两块本地 NVMe 的设备标识分别不同。第二台物理宿主已确认。初检时仍缺两个目标卷和可比对的聊天附件。当天后续已补入样本、重新冷备，并完成目的站双账号恢复验收。[后续执行记录](openscience-deploy-m6-cross-host-restore-20261127.md)

## 恢复目的地

初次核对时，源机和备份盘分别位于同一服务器的两块 NVMe。此前两台恢复演练客机也位于该服务器。随后在运维指定的目的机上只读核验了以下条件。[部署存储](openscience-deploy-m6-storage-20261125.md) · [双客机恢复](openscience-m6-restore-rehearsal-20261125.md)

| 目的机检查 | 实测结果 |
| --- | --- |
| 基础运行环境 | Ubuntu 24.04，128 个可用逻辑 CPU，约 225 GiB 可用内存。本地 Docker 29.2.1 可用，当前 Node 22.22.1 满足候选站要求。 |
| 存储和端口 | 两块本地 ext4 盘。数据目录约有 141.3 GiB 可用，部署账号对其现有工作父目录有写权限；主目录与 Docker 所在根盘约有 44.8 GiB 可用。四个候选端口 18860–18863 均无 TCP 监听。 |
| 配额存储准备 | 两个宿主挂载均未显示用户或组配额选项。现有受验方案使用独立存储客机；目的机缺少其启动命令 `qemu-system-x86_64`、`qemu-img`、`cloud-localds` 和 `genisoimage`。 |
| 应用准备 | 按固定镜像 ID 核对，本地 Docker 缺少 11 月基础镜像、工作区镜像，以及候选 API、PostgreSQL、UI 镜像。该宿主尚无既有的 deploy-m6 站点登记。 |

按当前双账号准入配置，两个实例需要 Docker 卷所在盘保留 36 GiB 可用空间（32 GiB 底线，加每个活跃实例 2 GiB）。导入镜像、分配存储介质之后仍需实测该盘余量。本轮只读检查了指定主机，未传输私有备份、创建卷或操作生产 9011。

## 初检时的异机演练缺项

1. **目的机工具链和镜像。** 主机身份和 SSH 入口已确认。需准备隔离的配额存储运行环境、候选镜像和备份暂存位置，按镜像导入后的实际余量核对准入。
2. **两个新卷和目的站登录路径。** 在目标机上为 A、B 各建独立的新卷，核对新文件系统 UUID、固定 UID/GID、内核硬限和恢复后的整树摘要。目的站需要识别原 A、B 平台身份，并将登录路由到这两份恢复卷。现有工作区归档不含平台账号数据库，账号映射和测试入口需单独接入。[部署候选身份与站点绑定](openscience-deploy-m6-site-20261125.md)
3. **可核对的聊天附件。** 在独立候选上用 A、B 各发送一份可区分的测试附件，记录所属项目、会话引用和内容摘要，然后取得含样本的一致性备份。恢复后分别登录，打开原项目、对话和本人的附件，按摘要核对并验证两户无法读取对方的会话及附件。若使用 11 月 25 日备份，验收范围限于该备份点已有的数据。
