# OpenScience M1 独立开发实例与恢复验证

M1 以一个持久管理目录为部署边界。管理器在这个目录内把每个 `(environment, user_id)` 绑定到一个工作区 ID、稳定的 Linux UID/GID 和一个 Docker 私有卷。进程退出或被回收后，再次调用 `ensure` 会按原映射恢复。身份参数由本地可信操作者提供，网页登录、身份换票及浏览器切号在 M2 接入。[隔离规划](../openscience-per-user-instances-plan.md)

## 同名项目与恢复

正式验收于北京时间 16:05–16:08 完成。A、B 分别经本人实例的后端 API 创建项目 `same-project`、文件 `notebook.txt`、一个普通会话和一个带该文件附件的项目会话。两人使用不同文本，模型返回受控回复。恢复时按原会话 ID 读取完整消息列表，比较规范化 JSON 的 SHA-256、附件和文件内容。发生新轮次时，以新增轮次后的最新记录作为下次恢复的对照。[九阶段数据及补充检查](openscience-m1-20261119.json)

| 实际操作 | A | B |
|---|---|---|
| 建立工作区 | UID/GID `34739590`，文件摘要前缀 `637b9349597f` | UID/GID `74880239`，文件摘要前缀 `ed14f2517c25` |
| 进程重启 | 第一代容器中进程启动时间更新，读回本人两组会话与文件 | 同样通过，自己的记录和附件均可恢复 |
| 两个实例均回收，换用同模板版本的另一镜像摘要并重建 | 原卷与 UID 不变，使用新的第二代容器 | 原卷与 UID 不变，使用新的第二代容器 |
| 强制结束 A 的后端进程，重新请求 A | 第三代容器恢复原项目、完整会话和文件 | 故障期间仍可读，第二代容器及数据保持一致 |
| 在本人实例查询项目会话，独立补测 | 本人的 ID 返回 200，B 的合成 ID 返回 404 | 本人的 ID 返回 200，A 的合成 ID 返回 404 |

同一用户并发两次 `ensure` 获得同一容器。A/B 已占两席时，第三个活跃实例被拒。换一个开发环境后，使用与 A 相同的用户 ID 获得另一 UID `8225323`、新卷、空项目列表和空普通会话列表。两个测试用户在各自正常入口中均没有观察到对方标记。

旧、新两份 M1 镜像均执行了真实项目活动检查。普通目录空闲且项目会话正在等待合成模型时，回收返回 `active_session`。恢复模型后助手回复正常保存。独立业务租约也能阻止回收；仅保留 SSE 订阅时，实例在测试空闲门槛后成功回收。正式验收和独立可见性补测的临时资源均已清理。

## 回收与准入

- `ensure` 串行分配工作区、核验实际容器和挂载并等待工作区就绪。同一注册表的管理进程共享文件锁。注册表经临时文件、原子重命名和刷盘写入。已绑定的卷缺失时，管理器报错，等待恢复原卷。
- `reap` 默认要求 30 分钟无业务。管理器先查业务租约，后端再汇总当前所有已加载目录的会话、待批准权限、待答问题及在途写请求。消息或会话状态变化会刷新活动时间。被动 SSE、心跳和状态轮询不延长空闲时间。M2 路由可用 `touch` 记录由用户主动触发、仅靠后端读取无法与轮询区分的导航动作。排空时阻止新的业务写入，再复查一次。忙碌或状态未知时保留实例。
- `restart` 重启原容器进程并换发凭据。`recycle` 回收后端、回环夹具及临时凭据，保留用户卷和注册记录。再次 `ensure` 时生成新容器代次。模型代理与工具消费真实额度前，仍要接入相应阶段的用户授权和计量。
- `set-image` 仅在本注册表已无实例容器时接纳另一份通过校验的本地 M1 镜像。用户卷、UID 和注册表保留。单机内存和磁盘的聚合保护、用户磁盘硬配额、异机备份及恢复演练见 M5。

单独运行本机管理服务的检查也通过。权限 0600 的 Unix socket 接受工作区请求，拒绝非工作区管理命令。将本次专用注册表的空闲门槛设为 2 秒、巡查间隔设为 1 秒后，巡查器自动回收了第一代容器。通过 socket 再次请求时，第二代容器沿用原 UID 和私有卷。停止服务和清理测试部署后，socket、临时容器和测试卷的剩余数量均为零。默认开发门槛仍为 30 分钟。

最终模板在单独的新后端上核对了实例凭据。健康、事件流、配置、项目和文件五类入口都拒绝缺失、错误和前代凭据。两个代次的合法凭据可以读取各自的健康、配置和工作区。最终镜像也通过后端模块、依赖锁以及继承层的核对。管理器 6 项故障边界用例、后端 5 项活动回归、沿用的开发补丁与 HTTP 边界 16 项、既有开发启动器 67 项测试均通过。

## 开发重放

需要本地 Linux Docker Engine、Buildx、Python 3，以及 M0 记录的后端与 Python 夹具镜像。下列命令在仓库根目录运行。请选择一个专用于此次独立部署的持久目录。后续每次通过同一目录管理这个部署，多个开发环境可以共用该注册表并用不同的 `dev-*` 环境名区分。丢失注册表时，应同时恢复原映射和私有卷。

```bash
m1_state="${XDG_STATE_HOME:-$HOME/.local/state}/nexpoly-m1-replay"
m1_image=$(python3 ops/openscience-per-user-dev/build_image.py | python3 -c 'import json,sys; print(json.load(sys.stdin)["image_id"])')
m1=(python3 scripts/openscience_per_user_dev.py --state-dir "$m1_state")
"${m1[@]}" init --image "$m1_image"
"${m1[@]}" ensure --environment dev-lab --user-id test-user-a
"${m1[@]}" ensure --environment dev-lab --user-id test-user-b
"${m1[@]}" list
```

默认每人使用合成模型，模型夹具兼作该工作区的测试客户端。M2 接入浏览器时，由受信路由管理实例凭据。

本地可信调用方可使用 CLI，也可以启动 Unix socket 服务。该服务只在注册表内创建权限 0600 的 `supervisor.sock`，默认每 30 秒巡查一次。进程结束后删除 socket，用户数据卷保留。每次 RPC 发送一行 JSON，例如 `{"operation":"ensure","environment":"dev-lab","user_id":"test-user-a"}`。支持 `ensure/status/stop/touch/begin/end`。其中 `stop` 使用与 `recycle` 相同的排空逻辑，`begin` 返回业务租约，`end` 须提交相应的 `lease`。服务仅供独立开发机本地启动。[实例管理器](../../scripts/openscience_per_user_dev.py) · [本机服务](../../scripts/openscience_per_user_service.py)

```bash
python3 scripts/openscience_per_user_service.py --state-dir "$m1_state"
```

本机保留了一组供 M2 联调的合成数据。注册表为 `~/.local/state/nexpoly-openscience-m1-dev`，环境为 `dev-m1`，用户为 `test-user-a` 和 `test-user-b`。两个用户均已回收运行进程，私有卷保留。要继续使用，向该注册表执行 `list` 或对相应用户执行 `ensure`。

单独执行双用户验收会创建并清理专属临时注册表、容器和测试卷，结果保存为一个新 JSON 文件。有两份已通过校验的不同开发镜像时，增加 `--restore-image <另一完整镜像ID>` 可以复测模板切换。使用单份镜像也可重放双用户回收与恢复。[验收驱动](../../scripts/ci/verify_openscience_per_user_dev.py)

```bash
m1_output=$(mktemp -d)
python3 scripts/ci/verify_openscience_per_user_dev.py --image "$m1_image" --output "$m1_output/result.json"
```
