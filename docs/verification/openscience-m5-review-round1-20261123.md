# OpenScience M5 第一轮修复验收

本轮覆盖 M5 复核的两项 P1。第一项是共享盘低水位时一个卷的错误阻断另一卷的限额设置。第二项是备份将文件空洞展开导致相同配额无法恢复。测试使用 dev-m1 存储虚机的独立写时复制副本。文件操作以测试账号原 UID 执行，内核使用真实 ext4 用户及组配额。

## 单卷故障时的全局保护

在 768 MiB 共享测试盘上施加占用，可用空间降到 83,881,984 字节。对选中一人的内核配额设置调用注入 I/O 错误，另一卷执行实际系统调用。监控分别确认各卷的设备、所有者和内核限制，记录无法确认的卷，并拒绝新增写入和启动。

| 注入条件 | 实测结果 |
| --- | --- |
| A 设置失败，随后交换为 B 设置失败 | 两个方向均报告 `unavailable`，健康卷的既有文件可读，以本人 UID 新建文件均得到内核 `EDQUOT`（122）。 |
| 排除故障，共享盘仍在低水位 | 两卷均已成功收紧。A、B 均收到 `EDQUOT`。释放空间后两人均能重新写入，原 2 GB 用户硬限继续生效。 |
| 共享盘已经越过恢复线，解除 A 或 B 的限制时失败 | 两个方向均维持拒写。两名用户实际写入都得到 `EDQUOT`，排除故障后均恢复。 |

监控将无法确认收紧结果的卷列在 `gate_errors` 中，只对单独核验成功的卷报告已收紧。如果解除限制失败、随后回滚成功，状态仍为 `unavailable`，两卷均会报告已收紧。

## 同配额恢复稀疏文件

在两个独立的 128 MiB ext4 文件系统上，以 A 的 UID 58161656 验收。源卷启用十进制 2 GB 硬限，目标卷起初没有用户限额。测试文件含头部、内部及尾部空洞，还包含一个确实写入的全零块。程序从文件系统读取数据区间，以 GNU PAX 稀疏格式打包，按区间恢复，同时校验完整逻辑内容摘要。

| 检查项 | 实测结果 |
| --- | --- |
| 文件逻辑长度 | 2,147,483,659 字节，超过用户硬限 |
| 文件实际分配 | 源和目标均为 12,288 字节 |
| 归档 | 完整工作区 tar 为 30,720 字节 |
| 恢复后的归属与配额 | UID/GID 均为 58161656，两卷用户硬限均为 2,000,000,000 字节。包含目录在内的 UID 实际用量均为 49,152 字节 |
| 数据完整性 | 源、备份、恢复整树摘要一致，另核对了最终文件的模式、长度及占块 |

ext4 还允许用户先预留空间、稍后写入。备份使用内核 FIEMAP 区分数据、空洞和尚未写入的预留区间。恢复用 `FALLOC_FL_KEEP_SIZE` 还原预留，再核对区间和文件长度。实测一个 8 MiB 纯预分配文件恢复后仍占 8 MiB。一个逻辑长度为零的文件保留了 256 KiB 预留。一个混有数据、内部空洞和末尾预留的文件前后均占 196 KiB。三份文件的工作区 tar 合计 30 KiB，恢复前后内核计给该用户的用量均为 8,888,320 字节。

**旧包兼容。** 原 A、B 两份封存备份的清单、归档和文件树摘要均通过校验。另用修复前的归档代码将一个逻辑长度 25,165,835 字节的稀疏文件制成普通 tar，在 8 MiB 用户配额下恢复。旧包没有空洞记录。空间不足时，恢复程序将全零块重新建为空洞，同时保留非零数据、所有者和完整内容摘要。本例从源文件 12,288 字节的实际占用恢复为 8,192 字节，差异来自历史归档无法区分已写入的零块与空洞。恢复回执记录了 `legacy_zero_recovery`。空间充足时，旧包沿用通常的恢复方式。

双账号网页在正常低水位下的保存、读取、删除及告警解除沿用此前的独立验收。本轮在存储端补测故障和恢复。M3/M4 与网页删除组合、并发启动阻塞、备份盘余量等后续复核项仍待处理。[逐项测量](openscience-m5-review-round1-20261123.json) · [双账号网页水位验收](openscience-m5-global-watermark-20261123.md)

相关回归通过 163 项 OpenScience Python 测试、8 项 Node 测试和 4 项网页工作区入口组件测试。Python 回归覆盖单卷设置失败、读回失败、外来卷身份、恢复中途失败，以及新旧归档、空洞、文件末尾预留和中断后的恢复清理。

修复也已安装到保留的独立开发虚机。关机后从同一组磁盘重新启动，五个模块的 SHA-256 与仓库一致，两个工作区仍是原 UID 和 2 GB 硬限，水位恢复为正常。维护前后的告警记录逐条一致，序号保持为 6。最终已关闭开发虚机及转发，四个配额卷均无容器占用。两块原配额盘、两块恢复盘和一块备份盘的 SHA-256 均与试验前一致。
