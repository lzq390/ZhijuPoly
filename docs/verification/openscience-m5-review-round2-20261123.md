# OpenScience M5 第二轮修复与开发验收

11 月 24 日对下述会话忙碌和目录刷新问题的定位、修复及复验见[第三轮记录](openscience-m5-review-round3-20261124.md)。

本轮复用独立 `dev-m1` 的 A、B 身份和已登记的 2 GB 硬配额测试卷。原 M1 私有卷保留。网页使用独立开发域名，存储使用测试虚机及一次性写时复制副本。

**本轮结论为暂缓 M6。** 在一次 PolyTAO 隔离复验中，B 查询对方草稿，网页在 7.024 秒后已读到本轮工具结果，最终助手记录也已写入 `finish=stop`。300 秒后原生会话仍为 `busy`，尚未记录完成时间。逐项复跑时，逆合成在 A 查询草稿后也持续忙碌超过 300 秒，工具和助手记录已有完成时间；PolyTAO 的 B 在准备草稿时也出现一次超时。两项都未完成本轮全套任务与扣费对账。解除阻断需要在同一开发候选上核实会话正常结束、随后一轮仍可执行，并完成两户工具对账。[逐项验收数据](openscience-m5-review-round2-20261123.json)

本轮 238 项本地回归全部通过，包括 179 项 Python 测试和 59 项 Node、Chromium 及前端测试。下文另外列出两个账号在真实开发服务上的实测结果。

## 存储准入与运维恢复

- 虚机与迁移程序共用存储锁。启动依据保存在池外的存储类型、文件系统 UUID 和布局摘要选择介质。已登记的池缺失或不匹配时在启动 QEMU 之前报错。旧池首次登记还要核对独立留存的 UUID、两份原镜像摘要、用户绑定和验收清单。存储配置在临时文件写完并落盘后才发布。回归覆盖缺盘、错误 UUID、安装遇到 ENOSPC 后重试及已有绑定冲突。
- 写前水位检查使用独立的服务处理通道。生命周期操作继续串行预留容量。重新配置与备份仍需独占注册表，存储端继续同步采样并检查内核配额。真实浏览器在 B 重新冷启动期间为 A 保存文件，A 在 B 完成登录交换之前收到 200。已运行的实例在低水位期间保留读删入口。
- 两个实例均已回收时，运维可在注册表中选定账号，核验私有卷、UID 和无挂载客户端后读出指定的项目文件。删除要求处于低水位，并核对与账号、文件系统、路径和内容绑定的读回执。实测 A、B 读到各自的同名测试文件，B 拒绝 A 的回执并保留原文件。A 删除经本人卷核验的 3 MiB 测试文件后水位恢复。冷账号的网页自助清理仍是开放内部用户前的验收项。[运维命令](../../scripts/openscience_m5_offline_file.py)

以下命令适用于已停机的独立开发账号。输出目录应为运维私有目录，文件名须为新路径。删除对象和内容应与用户确认，`confirmation` 取自同一次读回执。

```bash
registry="$HOME/.local/state/nexpoly-m5-native-01/src"
python3 scripts/openscience_m5_offline_file.py --state-dir "$registry" \
  --user-id test-user-a --path "$project_file" read --output "$private_copy"
python3 scripts/openscience_m5_offline_file.py --state-dir "$registry" \
  --user-id test-user-a --path "$project_file" delete --confirm "$confirmation"
```

## 备份容量与双账号恢复

备份先计算稀疏归档实际需要的空间，按目标文件系统串行准入，在写包前预分配并保留余量。新备份使用新名称发布。恢复代际记录两个账号各自的源、目标 UUID、硬配额及内容清单。若 A 已恢复，重试会核对 A 已发布的数据，B 可以单独继续。旧的独立备份仍可用原清单摘要恢复。

在一次性 ext4 副本上，A 的实占接近 2 GB 时，256 MiB 备份盘在写入前拒绝新包，余量保持不变，上一代 A、B 均可恢复。并发提交两份各自能放入、合计超过预算的包时，只发布了一份。B 恢复先遭遇 ENOSPC，再于发布前被终止，重试后两人的内容、UID 和硬限均正确，已恢复的 A 保留相同 inode。测试盘使用 16 MiB 保护余量。通用备份命令默认保留 16 GiB，目标部署需按实际配额、保留代数和并发预算核定。[配额备份程序](../../scripts/openscience_m5_quota_bundle.py) · [逐户恢复编排](../../scripts/ci/openscience_m5_guest_lifecycle.py)

独立备份命令的进程在预分配归档后被终止时，同一目标的下一次备份可校验暂存回执并回收该分配。实测中断时已分配 2,785,280 字节，重试后发布了完整的 B 包。既有完整归档和无法核验归属的目录会被保留。

## 镜像与网页组合

配额文件补丁按不可变镜像摘要校验并单独保存。使用老目录的实例可以继续使用原来的挂载路径。M3/M4、配额提示、网页删除和私有知识面板可在同一个开发候选启用。工具链验收通过显式测试选项模拟网关回执丢失，同时保留真实 Qwen 调用用于模型计量。普通启动使用正常服务配置。

首次组合演练在 PolyTAO 的网页确认处超时。草稿已经保存，点击时仍发送了一次更新，数据库里版本递增而任务尚未创建。修复后，未编辑的草稿直接确认页面所示版本，有新编辑的草稿先保存再确认。服务端继续核对版本与发起登录。浏览器回归覆盖这两种点击，以及重复点击和回执丢失。在开发栈实际丢弃提交回执后，A 在两台设备上共用限额，B 仍可提交。B 的聊天回执曾缺失，随后本人重新登录点击“继续查询结果”，恢复了指向原任务的唯一回执；账本核对该任务预留、执行、结算各一次，恢复期间仅三次草稿读取，新增扣费和模型调用均为零。

| 候选上的双账号检查 | 实测结果 |

| 六项网关工具 | 两个账号分别核对了性质预测、单体聚合和 DFT 的提交、列表、状态及结果。每人只能列出自己的 DFT 任务，对方查询状态、结果、单份文件和结果包均返回 404。每人核对了三份结果文件，提交回执丢失后的重试复用原任务。 |

### 切回原镜像后的实测

两台 Chromium 分别以 A、B 登录，最后一轮从同时开始登录到页面就绪分别为 46.290 秒和 27.171 秒。两个正在运行的后端均经 Docker 核对为原镜像。每人可打开原普通对话及项目对话，可找回候选期间自己的两条工具、模型会话，对方会话命中为零。两份模型原答及两份原项目笔记的内容摘要与回退前一致。

在原镜像的浏览器登录内，通过编辑器使用的文件 API 在私有测试文件上复核了内核硬限。A 实占 1,999,998,976 字节，剩余额度不足一个 4 KiB 块。两次保存均收到 507，两次均读回原内容；此时 B 保存并读回新内容。A 删除本轮占位文件后，同一保存恢复为 200。两个测试卷的 UID、文件系统 UUID 和每人 2,000,000,000 字节的硬限保持一致。回退前后的两户任务、权益和模型用量记录及适配器任务绑定均已比对。演练文件已清理。两个实例均已回收，测试虚机和转发已关闭，四个测试配额卷均无容器占用。五份保留磁盘镜像的摘要与演练前一致。

文件面板另有一项待修。首轮回退经面板打开两人的笔记并逐字核对成功，后续一次显式刷新 A 的项目根时，后端目录枚举返回 404。最后一轮核对了文件 API 返回的真实字节及摘要，尚未证明面板每次刷新都能列出文件。放行前需让两个账号在冷启动、创建文件和刷新后稳定看到各自的目录，并核对列表与文件内容一致。

本次两个镜像摘要来自同一份已审核的 11 月可执行内容，第二个摘要改变了构建标签。这个范围覆盖镜像选择、文件补丁与数据回退。下一次引入新可执行层或新数据格式时，需要用实际发布摘要重新审核源码并演练回退。目标介质、真实告警渠道、跨宿主恢复和拟开放并发档位仍按规划分别取证。

双账号同时冷启动时，原管理器 RPC 等待 35 秒、父页面等待 60 秒，两项都可能早于排队的实例就绪。开发入口现按两个实例的启动预算等待，期间分别复核每个登录，最后一次复核通过才签发页面。独立回环实验将两次启动各延时 33.5 秒，A、B 分别在 33.556 秒和 67.059 秒后取得自己的页面。另测等待期间撤权，另一登录仍可进入。这个容错预算与规划中拟开放并发档的 30 秒就绪 P95 分开验收。

在六工具验收与适配器验收重叠的一轮，B 的新消息元数据已落盘，文本部件约 128 秒后才出现。浏览器验收现按提交时的消息 ID 等待实际文本、工具结果和助手终态，同时记录耗时。该次延迟计入后续并发容量评估。

两用户组合验收沿用已登记的开发虚机和源注册表，要求两个测试实例已回收，测试虚机和专用转发就绪。为每轮创建新的私有工作目录和输出文件。在配备 Node 22 与 Chromium 的开发宿主运行以下命令。

```bash
python3 scripts/ci/verify_openscience_m5_watermark.py \
  --vm "$vm" --registry-root "$registries" --work "$new_work" --output "$new_report" \
  --combined-gateway-image sha256:6b6257257ed4c31a879ad2f525c288fc423121aeef55340da0825174a2338d1f
```

回退演练使用同一注册表和两个配额测试卷。在两个实例已回收、开发网页栈已经停止时，通过管理器的 `set-image` 切回已审核的原摘要，再执行下列命令。`candidate_reports` 中的 `m3.json` 和 `m4.json` 应来自刚验证的候选。浏览器据此查找升级期间的工具会话和模型原答，并复核其归属和摘要。每次填充、编辑和删除均使用本次演练的新文件名。

```bash
  --work "$new_rollback_work" --candidate-reports "$candidate_reports" \
```
