## 对话结果已经写入，为何网页还在等

在保留 Ganesha 默认并发槽的对照配置下，给原生存储调用加上耗时记录。此时已将导出属性有效期设为零，并启用了目录属性变更失效。一条消息部件读取耗时 161.719 秒，另一次历史记录读取耗时 170.547 秒。A、B 的后端线程都曾等待内核 `nfs_set_open_stateid_locked`。两项适配器验收都出现过单次历史读取超过 150 秒。原生会话结束前还要读取最后一轮消息，另一个历史读取也可能在会话结束后继续等待。单独看到工具结果或助手的 `finish=stop` 无法判断网页能否继续下一轮。

独立存储虚机使用 Ganesha 4.3 的 VFS 导出，宿主通过 Linux 6.8.0-31 的 NFSv4.1 客户端访问。开发配置把每个 NFS 会话的前向 RPC 槽数（`Slot_Table_Size`）从默认的 64 降为 1，以串行处理同一会话的文件打开、关闭等请求。适配器网页验收现在同时要求预期结果、对应助手记录的完成时间、正常结束标记和原生会话回到 `idle`，并在同一会话继续查询。计时使用原有的 300 秒预算。[存储服务配置](../../ops/openscience-per-user-dev/guest-nfs-exports.py) · [适配器网页验收](../../scripts/ci/verify_openscience_m3_adapters.mjs)

候选的正式复验关闭了临时跟踪。A 的 12 轮、B 的 8 轮均记录完成时间并回到 `idle`。从提交到浏览器读到完成状态，最长分别为 54.941 秒和 55.376 秒。两个适配器均在原会话继续查询了本人及对方任务。

| 双账号操作 | PolyTAO 和逆合成分别测得的结果 |
|---|---|
| 读取、编辑或确认另一账号的草稿 | 两个方向的网页请求均为 403，工具返回 `DRAFT_NOT_FOUND`。同一人的另一登录确认也为 403。 |
| 人工确认后丢失回执，再连续重试 | 两个账号各实际点击一次。每笔首次确认的响应为 503，重试关联原任务，再次确认复用原回执。四笔任务各提交、启动、结算一次，聊天中各有一份回执。 |
| 核对结果和个人用量 | 四笔本人任务均完成，另一个账号查询均为 404，个人用量清单中对方任务数均为零。 |
| A 用第二个登录再次提交，B 同时提交 | 两个适配器均为 A 返回 429，B 成功。B 提交后 A 仍收到 429，A 的额外草稿未建任务。 |

同一候选随后通过六项网关工具和 M4 的双账号复验。每人分别完成一次性质预测、聚合和 DFT 提交。两人只能列出自己的 DFT 任务，对方状态、结果、三份结果文件及结果包均被拒绝。A 通过 Chat Completions、B 通过 Responses 调用本地 Qwen，账本分别按 9,343/12 和 9,353/12 个输入/输出 token 结算。网页与 MCP 检索对方私有标记均为零，两人的引用与下载均匹配本人上传的原文。

## 冷挂载能按路径读文件，目录枚举却找不到它

用 A 的恢复测试卷建两个文件，卸载所有客户端后，以同一 UID 在 ext4 上改名，再通过登记的 Docker 卷冷挂载。原配置首次枚举仍列出旧名，按新名却能读到正确内容。另一组先删除再新建。在启用上述属性失效、仍保留目录分块缓存时，普通枚举返回 `ESTALE`，带文件类型的枚举返回 `ENOENT`，同目录已知文件仍可读。原生文件列表会把这里的 `ENOENT` 映射为网页 404。

测试虚机现关闭 Ganesha 目录分块缓存（`Dir_Chunk = 0`），并为四个 VFS 导出设置 `Attr_Expiration_Time = 0`。同一原镜像和 UID 下，离线改名、删除后新建各连续冷挂载四次，八次均在首次枚举获得正确文件名，文件字节也一致。B 的恢复卷使用六个并行读取者读同一笔记，96 次摘要均正确。本轮配置用时 1.079 秒，单次最长 270 毫秒。上一个对照配置分别为 0.781 秒和 178 毫秒，当时源卷同时在做会话跟踪。两次采样的后台负载不同，样本限于这台开发虚机和这份文件。更高并发和其他文件系统后端需要按实际介质测量。[回退网页验收](../../scripts/ci/verify_openscience_m5_quota_browser.mjs)

## 切回原镜像后的真实网页

同一候选完成工具、模型和知识验收后回收 A、B，将已登记的两个配额源卷重新挂到原镜像。两台 Chromium 分别登录，打开原普通对话和项目对话。每人找回候选期间自己的工具和模型会话各一条，另一账号的这两条会话均不可见。模型原答与笔记均按回退前的摘要核对。

文件列表逐次核对原生面板刷新发出的请求和实际可点击的文件行。A、B 各用已登录的编辑器文件接口创建一个同名文件，内容含各自标记。两人分别点击自己的文件，核对编辑器显示的完整字节，再用删除按钮确认。B 在 A 创建后看不到 A 的文件，在 A 删除后仍能刷新并打开自己的文件。离线预置的文件和原笔记也都出现在项目目录中。

填满 A 的内核配额时实占 1,999,998,976 字节。A 两次保存均收到 507，仍可读回原内容。此时 B 保存并读回成功，A 删除占位文件后同一笔保存返回 200。进入回退前和原镜像运行期间，分别按户比较任务、权益、用量记录和两个适配器的草稿任务绑定。

两次从回收状态同时登录，以各自真实网页就绪为终点。每次用不同的文件名重复面板操作。表中的次数统计冷启动后、创建后、删除后，以及 B 在 A 删除后的显式刷新。

| 回退轮次 | A 登录至网页就绪 | B 登录至网页就绪 | A / B 面板刷新返回 200 | A 满额保存 / B 保存 / A 释放后重试 |
|---|---:|---:|---:|---|
| 第一次 | 25.988 秒 | 44.787 秒 | 3 / 4 | 507 / 200 / 200 |

两轮中，原镜像读取的本人会话与模型原答摘要相同，对方会话命中为零。任务与计量账本的逐户行数和内容指纹均与候选结束时一致。两轮的 B 登录至网页就绪均超过 44 秒。拟开放档位仍需独立测量冷启动 P95、持续工具负载和磁盘余量。

本地回归共 243 项通过，包括 184 项 Python、34 项 Node 和 Chromium 测试，以及 25 项前端测试。演练结束时，源注册表已切回原镜像，A、B 实例均已回收，UID 和每人 2,000,000,000 字节的硬限符合登记值。四个配额测试卷均无容器占用，测试虚机、SSH 和 NFS 转发已关闭。原 M1 注册信息及五份保留磁盘镜像的摘要均通过复核。[验收数据与收尾记录](openscience-m5-review-round3-20261124.json)

## 已登记开发虚机的升级

新建导出时直接使用上述配置。升级已有的独立虚机时，先回收两个开发实例并关闭开发网页栈。专用转发正在运行时执行 `stop`，已关闭时直接执行 `start`。`dev_vm` 为该虚机原有的工作目录。

```bash
python3 scripts/openscience_m5_native_storage.py --vm "$dev_vm" stop
python3 scripts/openscience_m5_native_storage.py --vm "$dev_vm" start
```

启动会同时比较驱动和配置摘要。升级只接受已知旧版和当前版本，先占用本机专用转发端口，确认四个登记卷及带同一文件系统标记的别名均无容器引用，再逐卷核对挂载、UID 和文件系统 UUID。新配置启动失败时恢复原文件并重新启动服务。已经使用当前配置的运行实例可以重复执行启动命令。[开发存储入口](../../scripts/openscience_m5_native_storage.py)

现场保留的初版驱动与第二轮仓库基线有一行差异。初版依次枚举元数据，仓库版显式列出四个槽位。逐字节对比确认，两版在这台虚机生成相同的旧配置和导出编号。升级入口登记了这两个已核对的驱动摘要，同时校验旧配置全文。首次核对发现摘要不符时在替换前停止，核实差异后才用现场初版继续升级。

候选用 `scripts/openscience_m2_dev.py` 的 `--m5-quota-files --m3-adapters --m4 --verify-retries` 和登记的 `--m3-gateway-image` 启动。保留同一次启动，依次执行以下验收，各脚本通过网页分别登录两个账号。`reports` 为本轮新建的私有目录，`m2_state` 为开发网页栈的状态目录。

```bash
node scripts/ci/verify_openscience_m3_adapters.mjs --state "$m2_state" --output "$reports/adapters.json"
node scripts/ci/verify_openscience_m3.mjs --state "$m2_state" --output "$reports/m3.json"
node scripts/ci/verify_openscience_m4.mjs --state "$m2_state" --output "$reports/m4.json"
```

回收两个实例后，通过管理器把源注册表切回原镜像，再用 `verify_openscience_m5_rollback.py` 的 `--candidate-reports "$reports"` 核对这次候选上的会话和文件。回退演练启动普通网关。两次验收使用不同的工作目录和临时文件名。[回退命令与参数](openscience-m5-review-round2-20261123.md#切回原镜像后的实测)
