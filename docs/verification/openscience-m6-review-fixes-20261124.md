# M6 灰度前复核修复与回归

2026 年 11 月 24 日，在临时工作区、PostgreSQL 16、ext4 测试盘和独立 NFSv4.1 虚机复测 M3 至 M6 的六项复核问题。真实模型使用开发环境已固定的离线 Qwen2.5-7B。两套保留环境、原私有卷和生产 9011 均未参与本轮操作。

| 复核项 | 本轮实测 |
|---|---|
| M3 长对话人工确认 | 11 月镜像的真实会话存储和原生表单分别打开 PolyTAO、逆合成草稿。每份旧草稿后写入 1,005 条消息、2,412,000 字节无关正文。首次从旧记录找回准备消息，随后按消息和调用 ID 定点核验。每种表单连续确认两次都返回原任务 ID，另一会话的表单操作返回 403。原生验证使用独立工具上游夹具。Chromium 另验后台读取最近消息后，已打开的历史卡片及用户所填值仍在。 |
| M4 模型连接失败 | 独立 PostgreSQL 核账确认推理派发前的连接错误会释放预留。相同身份、代次、轮次和输入可以用原请求 ID 重试。送达状态不明的断流保留待对账估算。 |
| M4 原轮次期限与代次 | 网关在分词和预算等待后重新核对原轮次时限，工作进程在分词后、准入推理前再次检查。真实 Qwen 拒绝过期请求且回执为零，有效请求只产生一份回执，实结 7 个输入和 1 个输出 token。新计量记录留下工作区代次指纹。迁移前一笔 9 token 记录迁移后仍为 9，历史代次保持空值。旧版已释放请求缺少验证代次所需证据，重试需要新的请求 ID。 |
| M5 逐户恢复续跑 | 对已发布、回执丢失的恢复目标，对照固定备份逐文件核验 ext4 预留区间。一个零长度文件释放其 256 KiB 预留，或把同样大小的预留移至其他偏移，续跑均能识别。另一用户可独立完成恢复。旧版稠密备份仍按其记录的字段核验。 |
| M6 异常退出后的网页清理 | 在新建 Docker 工作区使 A 的后端退出、配套容器继续运行。低水位清理仅回收 A 的残留容器，原卷标记可读。B 的实例继续运行，冷清理入口拒绝接管 B。启动退避期间也可进入低水位页面。 |
| M6 大目录分页 | 新建 Ganesha 4.3/NFSv4.1 与 ext4 测试环境，放入 329 个可见文件和 333 个隐藏项。每页卸载并重新挂载，11 页返回全部 329 个可见文件，各出现一次，最慢一页 2.244 秒。Chromium 验证空分页继续、上一页和目录变更后回首页。新游标绑定用户、路径和目录版本，旧文件名游标可续读。 |
| M6 演练中断 | 96 MiB 演练文件在未命名 ext4 inode 中写完、核验后才发布。新建 8 MiB 小盘实际触发 ENOSPC，失败前后均有 2,048 个空闲块，目录中没有残片。正常盘完整写入、核对并删除 100,663,296 字节成功。 |

## 持续回归

默认 CI 已接入私有路由、草稿定位与模型转发的 Node 用例。后端分片使用独立的 `m4_model_test` 数据库，模型套件跳过会使必测任务失败。工作流策略和 121 项治理测试在按 Git 文件模式检出的临时目录通过。本轮执行本地等价步骤，远端工作流尚待提交触发。
