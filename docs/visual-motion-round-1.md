# 视觉交互优化：串行模块切换与手动验收

文中标注的本地证据仅用于定位当时的检查，不随仓库交付；仓库内文件仍使用相对链接。

更新日期：2026-09-09。交付入口：当前开发环境 **9001**；没有发布或重启生产环境。

## 当前效果

主模块采用 **400ms 完全淡出 → 200ms 空白 → 400ms 完全淡入**。在串行切换版本基础上，两段动画各从 500ms 缩短到 400ms；空白和其他交互规则不变。

| 阶段 | 画面 | 路由与交互 |
| --- | --- | --- |
| 离开检查 | 旧页面保持可见 | 共用原有结构同步；`false` 阻止，异常、拒绝及 1500ms 超时沿用放行规则 |
| 退出 400ms | 旧内容 opacity 1 → 0 | 保留旧路由、旧页面；内容区停止鼠标和键盘交互 |
| 空白 200ms | 只见现有工作区背景 | 完全透明后提交目标 URL、参数和模块；正常挂载新页面，透明起始帧建立后计时 |
| 进入 400ms | 新内容 opacity 0 → 1 | 不等待 API、iframe 或 3D 全部加载；进入完成后恢复内容交互与焦点 |

两段曲线都是 `ease-in-out`，只改变内容节点的透明度；侧栏和平台顶部栏不随之淡出。没有平移、缩放、模糊、白色覆盖层、中央旋转图标或虚构的加载进度。

名义总时长为 1 秒，不包括离开检查、DOM 初始化、建立起始帧与浏览器调度。200ms 是明确的空白计时，不是接口等待门槛；复杂模块首次初始化阻塞主线程时，实际空白可能更长。慢请求继续显示模块原有加载或错误状态。

首次打开平台、同模块内分页/标签/参数变化、任务 ID 更新及数据轮询不播放主模块切换。旧版 1 秒、0.70 → 1 的单向淡入和标题上浮/错峰实验已停用并清理。

本次按手动反馈增强局部效果：原来的 120–260ms 较短，页内透明度仅从 0.88 变化到 1，加上快速减速的曲线，变化容易被忽略。现在延长局部动效、采用更均匀的缓入缓出，并让已接入的页内标签从完全透明开始淡入。主模块的 400/200/400ms 节奏不变；不增加业务请求等待时间，不改变挂载规则，拖宽仍直接跟手。

## 统一动效参数

CSS 主来源：[motion.css](../frontend/src/styles/motion.css)。JS 读取必要计算样式，集中兜底见 [motion.ts](../frontend/src/lib/motion.ts)。没有新增运行时动画库。

| 场景 | CSS token | 规格 |
| --- | --- | --- |
| 主模块退出 | `--np-motion-module-exit` | 400ms，opacity → 0 |
| 主模块空白 | `--np-motion-module-gap` | 200ms，显式 opacity: 0 |
| 主模块进入 | `--np-motion-module-enter` | 400ms，opacity 0 → 1 |
| 主模块曲线 | `--np-ease-module` | ease-in-out |
| 控件颜色/边框/聚焦 | `--np-motion-control` | 200ms，位置与尺寸稳定 |
| 页内内容 | `--np-motion-tab` | 300ms，opacity 0 → 1，无额外空白等待 |
| 菜单与参数浮层 | `--np-motion-enter / exit` | 300 / 240ms，8px |
| 结果侧栏与主区联动 | `--np-motion-drawer-enter / drawer-exit` | 400 / 320ms，侧栏从右侧边界外滑入/滑出，主区同步平移 |
| 移动导航 | `--np-motion-drawer-enter / drawer-exit` | 400 / 320ms，20px |
| 遮罩 | `--np-motion-backdrop` | 240ms |
| 2D/3D 翻转 | `--np-motion-flip` | 400ms |
| 导航说明延迟 | `--np-motion-feedback-delay` | 120ms，不代表结构已保存 |
| 拖宽 | 无尺寸过渡 | rAF 合并，每帧至多提交一次，松手提交最终坐标 |

进入和退出曲线统一为 `ease-in-out`，让中间过程更容易看清。浮层位移为 `--np-motion-popover-distance: 8px`；移动导航保留 `--np-motion-drawer-distance: 20px`。结果侧栏不再使用 20px 短位移，实际距离根据面板宽度、并排区域与外边界计算，包含阴影退出余量。滚动条复用菜单的 300/240ms 显隐时长，停止滚动后的 700ms 等待保持不变。减少动态效果时仍直接呈现最终状态。

页内标签的快速切换会取消上一段动画，每个新目标均从 0 开始；不继承旧标签接近 1 的透明度，也不重新创建保活面板或 iframe。该淡入不锁定页面操作，不延后结果显示。

## 实现与边界

### 单一导航事务

[App.tsx](../frontend/src/App.tsx) 使用 [useModuleTransition](../frontend/src/hooks/useModuleTransition.ts) 统一侧栏、模块内部跨模块入口、命令和浏览器前进/后退。请求携带目标 ID、名称、完整 URL、知识检索条件、任务 ID、数据集和 history 方式，在透明提交点一起生效。

内部阶段是 `idle / guarding / exiting / blank / entering`。递增事务标识、具体 Animation 实例和清理函数共同排除过期完成事件、定时器及异步守卫结果。WAAPI 完成事件为主，时长 + 80ms 的 watchdog 兜底；启动延迟不消耗正常 400ms 动画区间。空白用明确的 `opacity: 0` 保持，不依赖结束后残留的动画填充。

[AppShell](../frontend/src/components/AppShell.tsx) 只呈现阶段、等待提示、既有内容节点和焦点。视觉状态采用外壳订阅，阶段推进不要求 App 及全部业务页面重新渲染。没有第二份工作区、旧 children 快照缓存、路由 key 或新增滚动容器。

| 新操作发生时 | 处理 |
| --- | --- |
| 守卫或退出中 | 只换最终目标；共用一次守卫和退出，不重置退出时钟；中间目标不挂载、不写 history |
| 空白中 | 在透明状态检查当前模块，提交最新目标并重新计时 200ms；不再播放透明页面的退出 |
| 进入中 | 取消淡入，保留当前透明度；检查通过后从该透明度淡出 400ms；拒绝则恢复当前页面可见 |
| 重复点击当前待切换目标 | 不重播、不重置动画 |
| 未提交前点击原模块 | 取消目标并恢复原页，不新增相同 URL 的历史条目 |
| 空白中覆盖刚提交的站内目标 | 替换本轮尚未显示的 history 条目；已开始显示的页面保留记录 |
| 空白中更新当前模块的任务/检索 URL | 替换尚未显示的条目，不多留一条无参数历史；页面开始显示后恢复原有 history 规则 |
| 前进/后退 | 使用浏览器已经更新的最新 URL 快照，不额外 push；旧页面迟到的任务 URL 更新不得覆盖该快照 |
| 新建项目/会话等命令 | 不进入目标替换队列；通过守卫后，在提交点执行一次；保留显式重载 Home iframe 的原命令语义 |

目标行立即标记为待切换，120ms 后出现短说明，直到最终完成才清除；当前高亮随路由提交更新。空白中已提交的模块可能已经初始化，不能承诺所有中间目标“从未挂载”。

### 焦点、浮层与降级

- 从退出开始到进入完成，内容区 `inert` 且对辅助技术隐藏；需要移走旧内容焦点时，先聚焦稳定的主区锚点，使用 `preventScroll`。
- 详情抽屉的模态监听同步识别模块退出，暂停抢焦点；模块所属的任务筛选 body Portal 在退出开始时关闭。侧栏项目菜单不被当成模块 Portal 清理。
- 移动端通过守卫后关闭导航并开始内容退出。遮罩在自身退场完成前继续阻挡点击；若导航仍覆盖，内容不开始淡入。完成后聚焦主区；主动取消导航仍返回菜单按钮，恢复淡入不会稍后抢走焦点。
- 运行中开启减少动态效果或标签页进入后台：取消视觉动画和空白等待，直接提交已获准目标并恢复可见。未完成的业务守卫继续有效；卸载只清理，不再提交导航。
- 内容容器由 WAAPI 独占透明度；减少动态效果时显式禁用其 CSS transition，避免旧全局 0.01ms 样式制造残留的一帧。
- 动画失败、意外取消或结束事件丢失都能清理透明度和交互锁。真实请求失败仍由模块原反馈处理。
- 选择当前模块或在提交前点回原模块，也会收起移动导航，但不重播模块动画。开发热更新重新连接 effect 时，恢复清理后保留的 DOM，不重放已取消的导航。

### 保留的首轮优化与业务规则

通用/知识抽屉、PolyTAO 结果栏、移动导航、菜单和参数浮层使用 `useMotionPresence` 完整进入和退出；子元素事件不算面板完成，退出中重开会废弃旧回调。兜底计时在目标元素的原生 `transitionrun` 时重新校准，避免 React 更新与实际动画启动间的初始化耗时截断动画；后台切换、减少动态效果与卸载均有清理。

结果侧栏的 `present` 只管理视觉节点、遮罩和焦点约束，**不再控制开关时的网格列或右侧 padding**。桌面并排区域在打开和关闭状态使用相同宽度；关闭时主区平移至工作区中央，打开时平移至并排位置，视觉关闭不会再次收回网格导致跳动。主区与结果栏由同一组阶段驱动，只在进入/退出期间启用位置过渡，稳定阶段不保留位置过渡。

`useDrawerMode` 依据模块容器实际宽度判断模式，不把左侧平台导航占用的空间算进去。通用默认阈值为 1280px，数据库分析/筛选保留原有专用阈值及 2K 宽度配置；知识详情由原来的 viewport ≥1280 改为容器 ≥1280 才并排，因此 1440×900 下是覆盖模式，主区不会被挤窄。PolyTAO 保留其 1160px 容器阈值。并排模式下主区采用能同时容纳侧栏的固定可用宽度，开关前后不缩放画板、不重建 iframe，也不逐帧改变宽度。

主区平移距离由面板宽度与间距决定，不是向左移动整块抽屉宽度。结果区域开关仍辅以透明度变化，主区不淡出、不缩放，也不加入模块切换的空白等待。仅外层非滚动框使用 `overflow: clip`，阻止焦点进入屏外抽屉时把整个工作区横向滚走；内层垂直滚动、高度链和工具栏位置保持原有职责。

`useDrawerResize` 保留 rAF 合并、最终指针坐标提交、失焦/取消/卸载清理、宽度边界、键盘调整和 2K 规则。拖宽期间不做尺寸追赶动画。`useFlipMotion` 跟随 400ms 视觉完成锁，数据准备和结构校验仍独立管理。

PolyTAO 结果栏也接入上述拖宽机制，移除原有独立的逐指针提交及页面 padding 过渡。关闭过程中遮罩、背景 inert 和焦点约束保留到退出完成，之后再恢复触发器焦点；结果区域的状态播报收敛到简短说明，不让整张结果列表反复播报。拖宽中关闭会解除拖动样式再启动正常退出，不会瞬间回中。

共享画板所有权、原有条件挂载和保活规则不变；不因动画额外克隆或重建 iframe。知识检索往返的同一画板节点保留，其他原本需要所有权切换而重建的情况仍遵循原逻辑。

没有改造用户隔离、状态保存/恢复、API 或任务生命周期，也不修改外部站点及 iframe 内部路由。Demo 仍从原挂载时点运行既有等待、进度和阶段推进，不被视觉阶段暂停、重置或加速。高通量满高、工具栏和内部滚动的现有改动保留；本轮没有编辑这些业务文件，也不将其他任务的高通量改动混入动效提交。
